# dsh-agent-run-control：运行控制服务

负责持久化运行请求、领取调度、Lease（租约）、续期、取消、终态及运行事件。
不导入 DSH（DeepSeek 智能体执行框架），不调用模型，不操作用户文件，不直接查询其他服务的数据库。
本服务的 PostgreSQL（关系型数据库）账号只拥有 `run_control` Schema（数据库模式）。

## 任务进入与状态

Chat（会话服务）把用户消息、公开接受事件和独立运行请求同事务保存到 Outbox（事务发件箱）。
发布器将运行请求发送到 `agent.commands.run.requested.v1`（运行请求主题）。请求只含身份与消息标识，不含用户正文。
独立的 `DSH_RUN_REQUESTS`（运行请求流）采用 NATS JetStream（持久化消息代理）的
WorkQueue（工作队列）保留策略：未确认请求不按时间过期，容量满时拒绝新发布，不淘汰旧请求。
数据库发件箱保留失败发布，代理恢复或释放容量后再发。

`run-control-v1`（第一版运行控制消费者）是持久消费者，所有副本共享，最多一个未确认请求，
确保按代理接收顺序入库。数据库提交成功后才 ACK（确认消息）；失败 NAK（否定确认）并延迟重试。
Inbox（事务收件箱）按事件标识去重，运行表另按会话和消息标识去重。
格式或身份冲突消息记录序号与错误类别后确认，避免毒消息永久阻塞队列；不保存原始敏感正文。

| 当前状态 | 允许转换 | 说明 |
| --- | --- | --- |
| `queued`（排队中） | `running`、`canceled` | 按入队顺序领取 |
| `running`（运行中） | `succeeded`、`failed`、`canceled` | 结果提交必须持有有效租约 |
| `succeeded`（已成功） | 不再转换 | 相同结果重传返回原结果 |
| `failed`（已失败） | 不再转换 | 租约过期或执行失败，不自动重跑 |
| `canceled`（已取消） | 不再转换 | 重复取消返回原结果，迟到结果被拒绝 |

调度事务使用短暂数据库行锁，保证跨副本全局并发上限和同会话串行，不在模型执行期间持有事务。
续期不能超过绝对执行截止时间。取得运行行锁后再次读取数据库实际时钟，避免把锁等待前的时间误当成当前时间。
默认租约 30 秒、绝对运行上限 120 秒、全局最多 64 个活跃槽位。这些是初始配置，不是千用户性能结论。

运行中取消立即拒绝续期和结果写入，但保留会话及全局槽位，直到执行端确认停止或旧租约到期。
**状态变为取消并不证明远程进程已被终止。** 将来的执行器必须在租约丢失时停止模型请求与工具操作。
当前已提供受限工作区能力签发及在线授权，检查到期、运行状态和尝试编号。
撤销仅阻止后续授权；已经通过最终检查的在途文件提交可能完成，尚无跨服务原子撤销协议。

租约丢失无法证明外部操作是否已经发生，因此转为失败，不自动重跑；人工重试和故障核对接口尚未实现。
`attempt`（尝试编号）当前最多为 1，保留该字段用于后续安全重试，不代表已有重试策略。

## 公共接口与执行端接口

API（前端聚合服务）代理下面的公共接口，所有查询及取消均校验租户与用户归属：

| 接口 | 含义 |
| --- | --- |
| `GET /api/v1/runs` | 按 `sessionId`（可选会话标识）、`limit`（页大小）、`after`（游标）查询 |
| `GET /api/v1/runs/:runId` | 获取运行状态和最终结果 |
| `POST /api/v1/runs/:runId/cancel` | 无正文，取消排队或运行任务 |

运行创建是异步的，提交消息返回 202 后列表可能暂时为空；前端应按会话查询，并用 `messageId`（消息标识）关联。
前端无权指定执行节点、尝试编号、工具、用户身份或直接创建任意运行。
公共响应不包含租约标识和执行节点标识。

执行端使用独立 JWT（JSON 网络令牌），签发者固定为 `dsh-agent-runtime-dsh`，
受众固定为本服务，主体为受信任执行节点标识。前端身份令牌和 API 服务令牌均不能访问执行接口。

| 内部接口 | 请求/返回 |
| --- | --- |
| `POST /worker/v1/claim` | 无正文；返回分配的运行、主体和租约；无任务时 `claim` 为空 |
| `POST /worker/v1/runs/:runId/heartbeat` | `leaseId`（租约标识）、`attempt`；返回租约到期时间 |
| `POST /worker/v1/runs/:runId/input` | 租约字段；返回冻结的授权输入快照 |
| `POST /worker/v1/runs/:runId/workspace-capability` | 租约字段；返回最长 30 秒、且不超过当前租约和截止时间的能力令牌 |
| `POST /worker/v1/runs/:runId/result` | 租约字段及成功输出，或受控失败类别 |
| `POST /worker/v1/runs/:runId/release` | 仅取消后、确认执行已停止时释放旧槽位 |

这些接口只定义执行协议，当前没有 `dsh-agent-runtime-dsh` 工作进程消费领取接口。
领取返回消息和会话标识；执行端另持有效租约获取输入快照，然后申请工作区能力。
未保存快照或定义没有工具时不签发；租约剩余不足一秒时先续期再申请。
执行节点凭据是受信任基础设施凭据，不能交给终端用户或模型。
领取响应丢失时不要盲目重复领取同一任务；未收到的租约最终失败，当前没有领取请求幂等键或恢复租约接口。

## 结果、事件与当前限制

终态和运行事件在同一数据库事务保存，发布确认失败会重发，接收方仍需按事件标识去重。
成功输出最多 32000 个 UTF-16（十六位统一字符编码）代码单元，按 Unicode（统一码）字符拆成小块发布，避免切断代理项或超出消息大小。
当前执行端一次回传完整结果，再生成 `run.output.delta.v1`（输出分片事件）和 `run.completed.v1`（运行完成事件）。
**这不是模型实时流式输出。** 真实模型增量和工具调用事件尚未实现。
结果先保存在本服务，通过运行查询读取；可靠写回会话后才发布成功输出与完成事件。

### 输入快照与回答投影

首次获取输入先检查节点身份、租约、尝试编号与截止时间，再通过独立服务凭据读取 Chat
的授权历史和 Catalog（定义中心）的精确版本。调用期间不持有运行行锁；外部读取结束后
重新检查租约，取消或过期时不保存、不下发新快照。后续获取仍检查租约，但复用同一持久快照。
校验运行、会话、消息、定义标识和版本一致，正文预算有上限；不接受执行端上传用户身份或提示词。

快照固定后，定义授权调整不会追溯改变该运行；需要立即停止已领取运行时应显式取消。
快照不是工作区访问能力，不授权读写文件；须另外申请短期令牌。
模型执行器还需执行定义中的轮数、输出词元与时间限制，
当前运行控制的全局截止时间并不替代这些定义级限制。

成功结果与 `result_projections`（结果投影票据表）、公开发件箱同事务保存。
后台通过独立 HTTP（超文本传输协议）接口写回 Chat，成功后才标记票据完成。
Chat 已提交但响应丢失或本地事务失败时，重复投递返回原助手消息，不制造重复回答。
失败按 1、2、4、8、16、32、60 秒退避，之后每 60 秒重试；没有静默丢弃或自动跳过。
每次外部调用限时 5 秒、响应最多 1 MiB（兆二进制字节），禁止重定向。

未完成的投影阻止同一会话继续领取，也阻止该成功运行的公开事件发布；其他会话仍能领取。
因此收到 `run.completed.v1`（运行完成事件）时，助手历史已经提交。
这一保证适用于升级后生成投影票据的成功运行；升级前已成功但尚未发布的事件仍保持旧语义。
运行查询可能提前看到 `succeeded`（已成功），它表示执行结果已提交，并不表示投影已完成。
前端可等待完成事件再刷新历史。错误/取消没有助手回答，不需要成功投影屏障。
当前执行节点仍是受信任基础设施：结果接口不校验模型输出来源，也不要求先调用输入接口。

升级前的成功结果不会自动生成投影票据，避免将早期测试回答补入真实历史。
投影长期失败会保留结果并阻塞对应会话，应监控待投影数量、最早等待时间和尝试次数；
人工修复、告警和死信处理接口尚未实现。快照会复制用户正文，须纳入加密、备份、删除和保留政策。

原来的 `DSH_EVENTS`（公开事件流）保持 24 小时重放窗口，独立运行请求不受这个窗口限制。
同一运行的输出与终态按顺序发布；跨运行、跨服务的公开事件没有全局业务顺序保证。
只有升级后新接受的用户消息会生成运行请求，不会自动执行旧消息或重发已有幂等请求来回填历史任务。

## 配置和运维

| 环境变量 | 含义 |
| --- | --- |
| `DATABASE_URL` | 专属数据库连接串 |
| `API_RUN_CONTROL_SECRET` | 前端聚合服务签名密钥 |
| `RUNTIME_RUN_CONTROL_SECRET` | 受信任执行服务签名密钥，与前一项不同 |
| `NATS_URL`、`NATS_TOKEN` | 消息代理端点与凭据 |
| `RUN_LEASE_SECONDS` | 租约秒数，默认 30 |
| `RUN_TIMEOUT_SECONDS` | 绝对运行时限，默认 120，最多 3600，不能小于租约秒数 |
| `RUN_MAX_ACTIVE` | 活跃槽位上限，默认 64，最多 1000 |
| `PORT` | 端口，默认 8080 |
| `CHAT_URL`、`RUN_CONTROL_CHAT_SECRET` | 会话服务地址和独立执行/投影凭据 |
| `CATALOG_URL`、`RUN_CONTROL_CATALOG_SECRET` | 定义中心地址和独立只读凭据 |
| `RUN_CONTROL_WORKSPACE_SECRET` | 签发工作区运行能力的独立长期密钥，不下发给执行器 |
| `WORKSPACE_RUN_CONTROL_SECRET` | 验证工作区服务在线授权查询的独立密钥 |

```powershell
npm run migrate -w @dsh-agent/run-control
npm start -w @dsh-agent/run-control
```

先初始化数据库模式和两条消息流、完成 Chat 和运行控制第二版迁移，再启动服务。
本服务的六个签名密钥必须互不相同，执行节点只持有 `RUNTIME_RUN_CONTROL_SECRET` 和自己运行的短期能力。
内部协议见 `dsh-agent-contracts/execution-openapi.json`（内部开放接口描述），禁止映射到公网网关。
初始化脚本不重置既有消费者位置；
如果既有运行流采用会丢弃未确认任务的配置，启动会拒绝服务，不能直接删除流重新初始化。
消费者暂时失败会重连；就绪检查同时检查数据库版本和消息代理消费状态。

生产必须使用 ACL（访问控制列表）限制运行请求主题只允许 Chat 发布；执行端不应获得 NATS 凭据。
当前本地代理共享令牌仅用于开发，不构成生产服务身份隔离。
请求流容量、收件箱/运行表长期增长、拒绝消息计数、租约失败、未发布事件都需要监控和保留政策。
租户公平调度、速率配额、计费、审计、优先级和跨地域高可用不在本版本范围内。

## 工作区在线授权

`POST /authorization/v1/workspace`（第一版工作区授权接口）仅接受 Workspace（工作区服务）的独立服务令牌，
不能用执行节点、前端聚合服务或运行能力令牌调用。工作区提交已验签能力中的运行标识、执行节点、
租约标识、尝试编号及当前工具；本服务从运行行和冻结快照取得用户、工作区与工具名单，不接受请求指定身份。
每次查询重新检查实时租约和运行状态，不凭尚未过期的签名令牌单独授予权限。

本服务不代理文件正文、不知道对象存储键，也不在授权时反向调用工作区。
Workspace 只依赖授权协议，不读取运行数据库；因此没有“运行控制等待工作区、工作区又等待运行控制”的调用锁环。
授权结果是一次检查，并非跨数据库锁或持久提交许可；强取消语义与执行中操作追踪仍待实现。

## 配额与审计接入（第三版迁移）

生产入口新增必需配置：`QUOTA_URL`（配额服务地址）、`AUDIT_URL`（审计服务地址）、
`RUN_CONTROL_QUOTA_SECRET`（配额调用密钥）、`RUN_CONTROL_AUDIT_SECRET`（审计调用密钥）。
这些密钥不得交给执行器。首次交付输入快照之前，按运行标识预留最大输出预算，失败则不下发输入。
输入已冻结之后不重复预留；因此升级时必须停止旧执行器、处理在途运行，不能把旧快照当作已预留证明。

运行生命周期元数据和配额关闭请求存入本库独立事务发件箱，由后台任务有界投递。
审计投递失败退避重试，不阻塞模型；结果未知、失败或取消不立即宣称并发安全释放，关闭延迟至总截止时间加宽限。
预留不做精确计费，配额感知排队与人工重试仍待实现。领取排序优先当前运行负载较低的租户与用户，
同会话顺序保持不变；这不是严格公平性或无饥饿保证。

## 内部指标

新增 `RUN_CONTROL_METRICS_SECRET`（运行控制指标密钥），与所有业务调用密钥分离。
`GET /metrics`（读取内部指标）输出队列、过期运行、支撑投递与回答投影积压，不含用户标签或运行正文。
正常延迟关闭配额的票据没有失败次数，不计入支撑重试年龄指标，避免误报。
指标来自共享数据库，多副本采集不能直接相加。详见 [监控接入](../dsh-agent-deploy/monitoring/README.md)。

## 模型计量接入（第四版迁移）

新增执行端 `POST /worker/v1/runs/:runId/usage`（提交运行模型计量）。
开始调用检查有效租约、冻结输入和连续序号；身份及模型来自本服务记录，不接受执行器自行指定。
本地调用状态与支撑发件箱同事务保存，异步投递到配额的用量接口，复用支撑重试积压指标。
同一执行身份可在取消或超时后补报已开始调用的最终计量，但不能因此获取输入或工作区权限。
原终态事件、结果投影、配额关闭语义不变；用量失败不触发模型重跑。
升级须停止旧消费者，不能让旧版本把新增 `model-usage`（模型用量）票据当作关闭配额处理。
详见 [计量协议与边界](../docs/model-usage.zh-CN.md)。

## 持久工作流步骤（第五版迁移）

运行控制拥有步骤状态、条件判断和中间结果，执行器不能自行跳步或扩展工具权限。
只有当前步骤可以开始模型调用；其步骤预算和顶层预算同时生效，结果完成前必须收到该步计量终报。
工作流未完整收敛时不能提交成功终态；最终输出必须与最后成功步骤一致。
本人进度接口不包含中间正文；原生命周期审计与最终回答投影不变。
详见 [工作流说明](../docs/workflow.zh-CN.md)。

## 并发调度（第六版迁移）

全局默认 64、每公司 32、每用户 2 个活动运行；满载留在排队，取消未确认停止的有效租约继续占槽。
等待超过 60 秒的可调度任务优先，仍保持会话顺序与投影屏障。活动负载一次聚合，新增查询索引。
支撑和回答投递各默认两个独立工作循环，公开事件及过期清理独立运行，不再每回写一次固定等待 500 毫秒。
数据库连接和等待操作有界，配置与限制见 [高并发说明](../docs/high-concurrency.zh-CN.md)。
调度限制不是完整配额感知排队；Quota（配额服务）依旧最终裁决。消息消费者和全局短事务锁仍是后续扩展瓶颈。
