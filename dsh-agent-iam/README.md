# dsh-agent-iam：身份与访问管理配置

采用 Keycloak（开源身份管理平台），交付本地 Realm（身份域）导入文件。
在部署工程启动后，访问 `http://localhost:8081` 管理界面，管理员账号为 `admin`，
密码来自本机 `.env` 的 `KC_ADMIN_PASSWORD`。导入文件不包含固定用户密码。

管理员创建测试用户并设置密码，再使用 `agent-web` 客户端登录。
客户端使用 Authorization Code（授权码）流程以及 PKCE S256（代码交换证明，SHA-256 算法）。
没有开启 Password Grant（密码授权）、Implicit Flow（隐式流程）或服务账号。
前端回调地址固定为 `http://localhost:3000/callback`，前端页面尚未交付。

访问令牌输出：

- `sub`（主体）：由身份平台管理的用户标识；
- `tenantId`（租户标识）：本地配置固定为 `local-dev`；
- `roles`（角色列表）：身份域角色；
- `aud`（受众）：`agent-platform`；
- `exp`（过期时间）：访问令牌有效期 5 分钟。

固定租户映射仅服务于本地联调。生产的多租户成员关系和租户切换还需要身份服务实现，
不能允许用户在个人资料中自行填写或修改受信任的租户标识。
服务已按动态签名租户做隔离测试，但这不表示本地身份配置已经提供多租户管理功能。

生产需创建单独的身份域配置，使用真实 HTTPS（超文本传输安全协议）地址、
准确的前端回调与来源、受控成员关系、持久化数据库和独立的管理访问入口。
本轮未运行 Keycloak 容器导入联调。
