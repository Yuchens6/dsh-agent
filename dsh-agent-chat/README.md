# dsh-agent-chat：会话消息服务

本服务是会话、用户消息和助手消息的唯一数据所有者，监听 8080 端口。
`/internal/v1`（内部第一版接口）仅接受已认证的 API（前端聚合服务）；
`/execution/v1`（执行第一版接口）仅接受 Run Control（运行控制服务），两类凭据不能互用。

PostgreSQL（关系型数据库）使用专属 `chat` Schema（数据库模式）与账号。
迁移文件位于 `migrations`；管理员先创建模式并授权，然后执行
`npm run migrate -w @dsh-agent/chat`。迁移使用数据库咨询锁和版本表，避免同时启动重复迁移。
生产应将迁移任务与业务工作负载分开部署。

所有用户资源读取、消息写入与授权都校验 `tenant_id`（租户标识）和
`owner_uid`（所有者标识）。不存在和不属于当前用户的资源统一返回 404。
外部调用者不能仅凭会话标识申请订阅能力。

创建会话按“租户 + 用户 + 幂等键”唯一；消息按“会话 + 幂等键”唯一。
相同键、相同请求返回原结果；键相同而内容不同返回 409。消息写入与
Transactional Outbox（事务发件箱）写入在一个数据库事务中完成。
每条新用户消息同时保存两条发件箱记录：公开接受事件和独立的运行请求。
运行请求写入失败时，用户消息及公开事件一起回滚。

后台发布器使用 `FOR UPDATE SKIP LOCKED`（锁定可用行并跳过已锁行）选择会话，
按发件箱序号发布，并在消息代理确认后标记成功。失败回滚标记，下轮重试。
NATS JetStream（持久化消息流）通过稳定 `eventId` 去重；消费者仍必须按事件标识实现幂等，
因为系统保证 At-Least-Once Delivery（至少一次投递），不承诺只投递一次。

订阅能力由本服务在所有权校验后签发，绑定用户、租户、会话、受众和权限；
有效期最长 60 秒。与内部调用密钥分开配置。

| 环境变量 | 含义 |
| --- | --- |
| `DATABASE_URL` | Chat 专属数据库连接串 |
| `API_CHAT_SECRET` | 验证 API 服务身份 |
| `CHAT_CAPABILITY_SECRET` | 签发事件订阅能力令牌 |
| `NATS_URL`、`NATS_TOKEN` | 消息代理地址和服务凭据 |
| `WORKSPACE_URL`、`CHAT_WORKSPACE_SECRET` | 工作区服务地址与独立签名密钥 |
| `CATALOG_URL`、`CHAT_CATALOG_SECRET` | 定义中心地址与独立签名密钥 |
| `RUN_CONTROL_CHAT_SECRET` | 验证运行控制服务，与前端聚合服务密钥不同 |

创建新会话先通过独立接口取得 Workspace（工作区服务）的归属工作区和 Catalog（定义中心）
授权的默认版本，再把绑定、会话和创建事件同事务保存。不接受客户端指定绑定。
调用各限时三秒；依赖不可用或租户无默认定义时返回 503，不创建未授权会话。
并行调用可能在会话失败后留下空工作区，后续复用，不进行跨服务事务或补偿删除。
幂等重放先查询已存在会话，不重新获取绑定；定义中心故障不影响原会话读取或消息保存。
旧会话空工作区保留，未自动迁移；后续执行器必须拒绝执行空绑定。
此阶段只保存会话和消息，不触发模型执行。
运行请求由 Run Control（运行控制服务）消费、去重并排队，但尚无 DSH 执行进程。
运行请求流满或不可用时保留待发布记录；重发已有幂等消息不会为旧消息补造运行请求。
升级时须先初始化独立 `DSH_RUN_REQUESTS`（运行请求流），再更新 Chat。
归档、删除和重命名尚未实现，不应从现有设计文档推断为已支持。

## 执行上下文与助手消息

运行控制调用 `GET /execution/v1/sessions/:sessionId/messages/:messageId/context`
获取绑定和有界历史。校验会话归属、用户消息归属、非空工作区；不接受调用者指定绑定。
最多取当前消息及之前的 20 轮用户消息，总正文不超过 64000 个 UTF-16（十六位统一字符编码）代码单元。
历史按用户消息顺序组装完整问答对，当前消息始终保留，超出预算从最旧轮次整轮舍弃并设置
`truncated`（已截断）。不会读取当前目标之后的用户消息，也不会把属于后续问题的回答放进输入。
此限制是字符预算，不等于模型 Token（词元）预算，执行器仍须遵守模型上下文限制。

`POST /execution/v1/sessions/:sessionId/assistant-results` 接收
`runId`（运行标识）、`messageId`（原用户消息标识）与 `output`（回答）。
同一运行与同一用户消息都只能有一条助手回答；相同内容重传返回原消息，冲突返回 409。
助手写入不产生用户接受事件，不递归触发模型执行。
运行状态的真实性由持有独立凭据的运行控制保证，Chat 不反向查询其数据库或 HTTP 接口。

历史查询按持久化顺序分页，游标仍使用消息标识。新增消息使用会话锁内分配的数据库序号，
不依赖不同进程时钟；旧数据通过迁移按原 UUID（通用唯一标识符）顺序分配序号。
助手可能在后来排队的用户消息之后入库，前端应使用 `replyToMessageId`（回复目标消息标识）展示关联，
而不是假定历史列表严格交替。助手记录还带 `runId`；用户记录保持原有字段。

升级须执行 `002_execution.sql`（第二版执行迁移）。本阶段支持可信测试结果投影，仍未启动真实模型。
## 会话管理补充（第三版迁移）

`PATCH /internal/v1/sessions/:sessionId`（部分修改会话）经聚合服务映射为同名公开资源路径。
请求必须包含 `expectedRevision`（预期修订号），并至少提供 `title`（标题）或 `archived`（是否归档）之一。
冲突返回 409；成功修订号加一。列表与详情同时返回归档状态和修订号，列表保留已归档会话以便恢复。
归档不删除历史，不取消已接受任务、不阻止在途回答投影；阻止新的用户消息，已有幂等请求可重放。
恢复使用当前修订号将归档状态设为假。会话物理删除与跨服务清理尚未实现。

## 变更审计与指标（第四版迁移）

会话创建/修改、用户消息接受和助手投影在本库同一事务生成审计票据，不记录标题、提示词或回答正文。
相同幂等请求重放不重复记审计；修订号更新每次生成一条修改记录。审计本地写入失败会回滚业务事务。
独立后台任务投递失败时保留票据并退避重试，网络投递不持有会话行锁，也不要求审计在线才能接受新业务。
新增 `AUDIT_URL`（审计地址）、`CHAT_AUDIT_SECRET`（审计写入密钥）和 `CHAT_METRICS_SECRET`（指标密钥）。
`GET /metrics`（读取内部指标）提供审计与事件发布积压，凭据不具备业务接口访问权。
详见 [监控接入](../dsh-agent-deploy/monitoring/README.md)。

## 并发与消息准入（第五版迁移）

新增跨副本的用户新消息窗口限流，以及本服务未投递运行请求的用户/会话积压门禁。
既有幂等请求先返回旧结果；新消息拒绝不落库、不消耗计数。不是全链路队列长度限制。
后台默认两个发布循环；不同会话可以并行，同会话仍通过行锁保持顺序，有积压时不固定等待 500 毫秒。
数据库默认 10 个连接、64 个额外等待操作，满载明确拒绝，并导出容量指标。
配置、重试与生产限制见 [高并发说明](../docs/high-concurrency.zh-CN.md)。
