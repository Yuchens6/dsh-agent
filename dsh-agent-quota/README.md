# dsh-agent-quota：配额与积分服务

独立 TypeScript（带类型的 JavaScript）服务，拥有 PostgreSQL（关系型数据库）的 `quota`（配额）模式。
运行控制通过 HTTP（超文本传输协议）预留；不访问运行控制数据库，不读取模型输出。

## 已实现

- 用户及租户级并发预留上限，按 UTC（协调世界时）自然日计算的保守输出词元预算。
- 按租户数据库行锁串行决策，多副本不依赖本机计数；同一运行标识预留幂等。
- 预留关闭释放并发，不退回当日预算。关闭先于预留到达时保存墓碑，拒绝迟到预留。
- 预留到期退出并发统计，保留账本；跨日仍在运行的预留继续占并发，预算记在预留日。
- 当前用户可通过聚合服务查询自己的配额；不能指定其他用户或租户，不能调用预留接口。

生产运行控制在下发模型输入之前强制预留，数量为定义的最大模型步骤数乘以单步最大输出词元数。
预留有效期为运行总截止时间加 60 秒宽限。成功终态异步关闭；失败及取消保守等到这一期限再关闭。
配额拒绝使运行失败为 `QUOTA_EXCEEDED`（超出配额）；服务不可达则拒绝下发输入，不能无额度执行。
系统不自动重试模型；已预留但输入未交付或结果未知，仍保留当日预算，避免重复消费穿透限制。

保守输出预算不是精确计费。现可独立启用按供应商用量与配置价格计算的积分账户；没有月度预算。
供应商实际费用不能由这个值推算；模型实际遵守输出限制仍依赖供应商协议行为。
并发约束针对持有有效预留的执行，不证明到期后网络远端已无在途请求；沿用运行器与工作区的取消边界。
预留冲突不会让已领取任务返回队列，避免隐式重跑副作用；高负载下仍需完善配额感知的队列调度。

## 配置与接口

| 环境变量 | 含义 |
| --- | --- |
| `DATABASE_URL` | 本服务专属数据库连接串 |
| `API_QUOTA_SECRET` | 前端聚合服务查询身份密钥，至少 32 字节 |
| `RUN_CONTROL_QUOTA_SECRET` | 运行控制写接口密钥，与查询密钥不同 |
| `QUOTA_USER_ACTIVE` | 用户并发上限，默认 2 |
| `QUOTA_TENANT_ACTIVE` | 租户并发上限，默认 32 |
| `QUOTA_USER_DAILY_OUTPUT_TOKENS` | 用户每日输出预算，默认 1,000,000 词元 |
| `QUOTA_TENANT_DAILY_OUTPUT_TOKENS` | 租户每日输出预算，默认 100,000,000 词元 |
| `POINTS_BILLING_ENABLED` | 新运行积分计费开关，默认 `false`（关闭）；所有副本须一致 |
| `PORT` | 服务端口，默认 8080 |

当前统一配置适用于所有租户，不提供在线套餐编辑接口。降低配置不会中断已授权的运行，只阻止后续超额预留。
`POST /control/v1/reserve`（预留）、`POST /control/v1/close`（关闭）仅接受运行控制凭据；
`GET /internal/v1/quota`（本人用量）仅接受聚合服务凭据；外部入口为 `GET /api/v1/quota`。
三个英文 HTTP 方法分别表示提交、提交和读取。
结构见 [内部支撑协议](../dsh-agent-contracts/support-openapi.json)。健康检查不返回用户数据。

首次部署先创建本服务数据库角色与模式，然后用 `node dist/migrate.js`（迁移命令）执行到第三版迁移，
再用 `node dist/main.js`（启动命令）启动。详见 [部署说明](../dsh-agent-deploy/README.md)。
无 Redis（内存数据存储）依赖：第一版采用数据库锁保证一致性；引入缓存应以原生数据库并发压测结果为依据。
工作区存储限额仍由工作区服务自己的事务保证，未迁移到本服务。

## 供应商用量统计（第二版迁移）

`POST /control/v1/usage`（写入模型用量）仅接受运行控制凭据，并核对已存在的预算预留所有者。
记录以运行、尝试和调用序号去重，允许乱序投递；最终用量不可改写，未知计量不当作零。
`GET /internal/v1/usage`（内部本人统计）通过聚合服务映射到 `GET /api/v1/usage`（公共本人统计），
支持 `day`（UTC 日期）查询参数，默认当天。统计最终一致，只汇总已知用量，并单列未知和待报调用。
词元总数用十进制字符串表示；统计不扣减或退还原有保守预算。
完整字段、日期归属与缺失边界见 [模型用量说明](../docs/model-usage.zh-CN.md)。

## 积分账户（第三版迁移）

公司发放后硬分配到员工独立账户；运行前冻结积分及计价版本，逐次用量幂等扣费，全部结清后解除剩余冻结。
缺价格拒绝启动，缺计量或余额不足保留待结算，不借用其他员工积分。
公共入口 `GET /api/v1/points`（本人积分）与 `GET /api/v1/points/ledger`（本人流水）只读；
发放、分配和发布价格由可信运维通过 `node dist/points-admin.js --file command.json`（管理命令）执行。
价格、兑换比例、冻结额、舍入规则及限制见 [积分计费说明](../docs/points-billing.zh-CN.md)。
默认关闭，未接支付、退款或公司管理员自助管理；单次冻结额不是模型费用的绝对上限。
