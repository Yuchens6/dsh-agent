# dsh-agent-knowledge：知识访问服务

提供可配置的 RAG（检索增强生成）：PostgreSQL（关系型数据库）的全文、结构化、纯图谱及无向量混合检索，无需向量模型；保留 [LightRAG（轻量知识图谱检索增强生成）v1.5.7](https://github.com/HKUDS/LightRAG/releases/tag/v1.5.7) 固定 `POST /query/data`（结构化检索）适配。检索证据交给现有 DSH（DeepSeek 智能体执行框架）生成答案，不修改上游或重写模型循环。无向量方案的模式配置、独立账号、迁移与语料导入见 [实施手册](../docs/nonvector-rag.zh-CN.md)。

当前为只读检索接入：管理员管理知识源与文档导入；没有用户文档上传界面、自动同步工作区文件、图谱编辑、任意数据库查询或动态 MCP（模型上下文协议）加载。知识工具与文件工具共用运行预算和取消机制，但使用独立授权凭据。

## 架构与隔离

```text
已审核定义中的 knowledge.search（知识检索）
  → DSH 子进程发起工具请求
  → 父进程向运行控制申请知识专用短期能力
  → 知识访问服务在线核验租约、步骤和定义允许的源
  → 显式核验 tenantId + uid（租户与用户）是否为该源读者
  → 管理员选择的 PostgreSQL 审核语料检索或固定 LightRAG 端点检索
  → 返回结果前重新在线核验
  → 有界文本、实体、关系与引用标识送回 DSH
```

运行器不持有 LightRAG 访问密钥；工作区凭据、执行节点凭据和知识能力不能互换。前后两次检查不能追回已经发送的数据，不宣称跨服务原子撤销。服务不可达、状态取消或租约失效时拒绝返回结果。

一个 LightRAG 端点视为一个语料库，不将用户参数拼入上游地址，不臆造工作区请求头。不同私有语料库应使用不同的已配置端点，并在上游使用独立 `WORKSPACE`（工作区命名空间）与存储目录。端口不同但错误地共享同一上游存储仍会混数据，部署人员必须验证底层隔离。

一个源配置多个读者表示**有意共享整库**；只配一个用户表示个人库。授权采用精确租户/用户匹配，没有默认全员或通配符授权。授权文件只允许可信运维修改，变更后重启知识服务生效；定义授权和源读者授权缺一不可。这是静态受控授权初版，没有在线授权管理数据库。

## 工具与结果

`knowledge.search` 在模型侧名称为 `knowledge_search`（知识检索）。参数：

| 参数 | 含义 |
| --- | --- |
| `sourceId` | 管理员配置的源别名；必须同时在定义 `knowledgeSources` 和源读者权限内 |
| `query` | 问题，3–2000 个字符 |
| `keywords` | 1–8 个关键词，每项最多 80 字符；由当前模型提供，不启动 LightRAG 关键词生成 |
| `mode` | 仅 LightRAG：`mix`（图谱与向量混合，默认）、`hybrid`（局部/全局图谱混合）、`local`（局部实体）、`global`（全局关系）；不能覆盖管理员配置的无向量模式 |
| `filters` | 可选结构化等值条件，最多 8 个管理员允许的标量字段；只约束结构化/混合模式的记录部分，其他模式拒绝非空条件 |
| `limit` | 各类结果最多 1–10 条，默认 5 |

LightRAG 上游不生成最终答案，显式传入两组关键词并关闭重排序；其入库及检索可能需要模型/向量费用，此类费用不进入平台 DeepSeek 积分账本。PostgreSQL 四种模式不调用额外语言模型或向量模型，导入已审核数据，最终回答仍有原来的语言模型费用，数据库也有资源成本。

返回 `chunks`（文本片段）、`entities`（实体）、`relationships`（关系）、`truncated`（是否裁剪）。文本总预算 16000 个代码单元，单片段最多 4000，各类最多 10 条。引用是源别名与内容相关的不可读摘要标识，不返回上游文件路径、源地址、密钥或任意元数据；正文自身可能含敏感信息，仍依赖正确的语料授权，不提供内容脱敏保证。

引用便于当前回答核对证据，不是持久证据下载接口。图谱项不保证全部能映射到已返回片段；不得为没有片段支持的论断伪造引用。返回的资料是数据而不是指令，不能提升工具权限。

网络上游请求固定路径、禁止重定向、15 秒超时、响应最大 1 MiB（兆二进制字节）。授权查询超时 2 秒、最大 16 KiB（千二进制字节）。检索前后都检查权限；默认最多 16 个在途请求，不建立无限等待队列。上游畸形、失败、超时或超限返回统一依赖不可用，不泄漏上游错误内容，不自动重试模型。

## 配置与启动

需要先构建仓库。将 [配置示例](.env.example) 复制到私有目录，根据实际环境填写，不使用示例口令。将 [源示例](sources.example.json) 复制到私有目录，替换真实用户 `sub`（身份主体）和租户。

| 进程 | 增加的配置 |
| --- | --- |
| 运行控制 | `RUN_CONTROL_KNOWLEDGE_SECRET`（签发能力）、`KNOWLEDGE_RUN_CONTROL_SECRET`（验证在线授权查询）；两把密钥必须一起配置，且与其他服务密钥不同 |
| 知识服务 | 同上两把密钥、`RUN_CONTROL_URL`（运行控制地址）、`KNOWLEDGE_SOURCES_FILE`（源配置文件）、每个源指向的凭据环境变量 |
| DSH 执行器 | `KNOWLEDGE_URL`（知识服务地址）；不注入上游密钥或上述签名密钥 |

知识服务默认只监听 `127.0.0.1:8090`。运行控制示例端口 8085 只是待配置值，不意味着原生整个平台已经部署。生产环境上游源必须使用 HTTPS（加密超文本传输协议）。

```powershell
# 仓库根目录，配置文件路径按实际位置替换。
node --env-file=.local/knowledge/knowledge.env dsh-agent-knowledge/dist/main.js
```

服务不会自动创建用户/源/文档，也不会启动 LightRAG。`/health/ready`（就绪检查）对 PostgreSQL 检查知识表可读及所有配置语料已导入；LightRAG 仅验证源配置，不验证上游索引或可达性。均不能替代实际检索验收。所有业务接口仅内部访问，不新增公网路由。

定义示例：[knowledge-agent.v1.json](../dsh-agent-catalog/definitions/knowledge-agent.v1.json)。先复制并填写实际模型名、知识源标识，再通过原有受控发布命令授权给目标租户。不会自动发布或切换默认智能体；旧会话仍绑定旧版本。

```powershell
# 已在本进程配置定义中心管理账号 DATABASE_URL 后执行；文件路径相对 catalog 工作目录。
npm run publish -w @dsh-agent/catalog -- --file definitions/knowledge-agent.v1.json --tenant local-dev --default
```

无向量后端新增独立 `knowledge`（知识）模式第 1 版迁移，预先创建管理账号与只读账号、迁移并导入语料；只使用 LightRAG 不需要知识数据库。运行控制仍需要第 7 版迁移。先更新协议消费者、运行控制和知识服务，再更新执行器，最后发布带新工具的定义，禁止旧执行器领取知识定义。旧定义未声明知识工具时保持原行为。

## 验证与剩余边界

执行 `npm run check`（类型检查、构建和测试）。[知识测试](../tests/knowledge.test.ts) 覆盖权限、能力、工作流/取消、限制及真实 DSH 子进程到两种后端的认证 HTTP（超文本传输协议）链路；[无向量专项测试](../tests/nonvector-rag.test.ts) 验证中文、过滤、图遍历、只读角色、版本与原子回滚。模型与 LightRAG 使用本机夹具，数据库使用 PGlite（轻量数据库引擎），不代表现有业务库已迁移、实际上游已部署或真实供应商验收。

部署、费用、真实验收步骤与来源依据见 [LightRAG 接入手册](../docs/lightrag-integration.zh-CN.md)。尚无知识访问持久审计、知识检索独立积分结算、自动上传同步、源管理页面、集群部署验收或生产容量结论。
