# dsh-agent-runtime-dsh：DSH 执行服务

2026-10-08 已使用根目录环境配置完成真实 DeepSeek 模型、原生技能与两步工作流的小规模验收。
可用 `npm run test:live:model -- --live`（会产生实际模型费用）复测；测试子进程完成后退出，不启动全部平台服务。详见 [真实模型验收记录](../docs/live-model-test.zh-CN.md)。

第十八阶段接入官方 Skill Registry（技能注册表）与 Tool Skill（技能加载工具），替换全部技能正文的系统提示词拼接。
支持按需加载、`/技能名` 显式调用与独立调用策略；原生技能和远程工具共享单次运行及跨步骤预算。
不扫描宿主机目录，不执行技能脚本。配置、兼容性与尚未接入的持久化边界见 [原生技能说明](../docs/native-skills.zh-CN.md)。

第十七阶段移除平台固定轮数／字符数的上下文裁剪，完整聊天记录按原始角色导入原生 Session（会话），
接入官方 Token Meter（词元估算器）和 Compaction（上下文压缩）。摘要单独计量但不作为用户回答预览。
目前仍按运行重建会话，尚未跨轮保存原生工具事件和压缩检查点，详见 [原生上下文管理](../docs/native-context.zh-CN.md)。

第十六阶段使用 DSH 原生 Workflow（工作流）和 Worker Thread（工作线程）引擎；平台只提供获准输入、受限工具、计量和状态桥接，不再请求下一步。详见 [原生工作流设计](../docs/workflow.zh-CN.md)。

第十五阶段接入固定版本 `dsh-llm-retry`（模型请求重试插件）：默认暂时性错误最多额外重试 2 次，
每次尝试单独计量、占用既有模型调用预算，共用原截止时间；不重做成功工具、不重跑已失败的整个任务。
新增 `retrying_model`（模型重试等待）公开状态，详见 [模型重试设计](../docs/model-retry.zh-CN.md)。

第十四阶段新增可选 `knowledge.search`（知识检索）工具及 `KNOWLEDGE_URL`（知识服务地址）。仅在定义显式允许、
知识源已授权时注册，走独立能力与在线租约校验，不加载任意 MCP（模型上下文协议）工具；详情见
[LightRAG 接入](../docs/lightrag-integration.zh-CN.md)。下文“三种工具”描述适用于未启用知识的旧定义。

第十三阶段已接通实时正文预览、工具状态和有界进度确认；下文旧阶段“只回传完整回答”描述已被扩展。
仅公开正文，不公开内部推理。依赖运行控制第 7 版迁移，详见 [实时反馈说明](../docs/realtime-feedback.zh-CN.md)。

本项目把 DSH（DeepSeek 智能体执行框架）接入现有多租户系统。每个工作进程依次领取任务，
每次运行创建独立子进程；执行完毕或取消后退出。它不是“一用户一个 Pod（容器组）”，
也不将用户工作区挂载为宿主机目录。用户文件由 Workspace（工作区服务）通过授权接口管理。

## 服务职责与依赖

| 模块 | 职责 |
| --- | --- |
| `main.ts`（启动入口） | 配置校验、领取循环、健康检查、优雅停机 |
| `client.ts`（服务客户端） | 调用 Run Control（运行控制服务）；按次申请能力后调用工作区 |
| `worker.ts`（任务工作进程） | 续租、超时、工具次数限制、回传终态；不自行重跑任务 |
| `executor.ts`（子进程管理器） | 创建固定代码子进程、校验 IPC（进程间通信）消息、终止并等待退出 |
| `child.ts`（子进程入口） | 接收单次输入、转发工具请求、返回最终文本 |
| `engine.ts`（智能体适配） | 装配最小 DSH 核心、已审核技能与工具、模型步骤上限 |
| `skills.ts`（原生技能适配） | 把冻结技能注册给官方插件，不自建技能目录或加载器 |
| `workflow.ts`（原生工作流适配） | 调用官方工作流引擎；固定可信模板、受限子智能体及状态报告 |
| `provider.ts`（模型适配器） | 官方 DeepSeek 协议、显式凭据、有限暂时性错误重试策略 |
| `retry.ts`（重试配置） | 次数与退避上限校验，不允许无限重试 |

服务仅依赖公共协议包和已发布的上游包，不导入其他服务业务代码，不访问其他服务数据库。
使用固定版本的 DSH 核心包 `0.1.1-rc.2` 和 Cordis（插件生命周期容器）`4.0.1`，
版本与完整依赖记录在 `package-lock.json`（依赖锁文件）中。没有修改上游源码。

这里没有启动完整默认演示程序，也没有使用客户端 SDK（软件开发工具包）远程控制默认配置的执行器。
选择直接组合上游核心，是为了只注册平台允许的能力，同时保留模型循环与插件生命周期实现。
升级上游版本时必须重跑子进程与跨服务测试，不能把预发布版本当作稳定兼容承诺。

## 一次运行如何完成

1. 工作进程凭自己的身份领取任务并续租，从运行控制取得已冻结的输入快照。
   第七阶段起，生产运行控制在首次下发输入前强制完成配额预留；拒绝配额不会启动模型。
2. 子进程加载系统提示词，将已审核 Skills（技能）交给原生插件按需或显式加载，注册工具白名单。
3. 模型提出远程工具调用，子进程通过进程间通信发送给父进程。父进程校验名单和次数，再申请短期能力令牌。原生 `skill`（技能工具）只在子进程内读取批准内容，但仍消耗共享预算并等待进度确认。
4. 工作区服务在线核对有效租约，并从运行绑定确定用户和工作区。模型不能传入用户、租户或工作区标识。
5. 完整回答产生后等待子进程退出，再向运行控制提交结果。运行控制负责可靠投影到 Chat（会话服务），并发布完成事件。

当前只有 `workspace.list`（列文件）、`workspace.read`（读文本）、`workspace.write`（条件写文本）。
模型侧工具名使用下划线，例如 `workspace_read`。写入必须带 `expectedVersion`（预期版本）；
空值仅用于新建，已有文件必须使用读取到的版本。冲突或其他远程工具失败会结束当前运行，不自动重试写入。

历史消息按原始用户／助手角色导入 DSH 会话种子，当前用户消息单独提交，不再包装成一条 JSON（数据交换格式）用户消息。
子进程内由官方插件管理词元压力、摘要和溢出恢复；原生内部事件尚未跨运行持久化，文本导入不等于完整原生恢复。
输出仅接受正常完成的非空文本，最多 32,000 个字符；截断、错误及超时不会伪装成成功回答。
正文预览通过有界进度通道实时推送；最终结果投影仍保留兼容分片，不应重复拼接。

## 配置与启停

| 环境变量 | 含义和默认值 |
| --- | --- |
| `RUNTIME_ENABLED` | 是否领取任务；默认 `false`（关闭） |
| `RUN_CONTROL_URL` | 运行控制服务地址；必填，只允许源站地址，不允许路径或内嵌凭据 |
| `WORKSPACE_URL` | 工作区服务地址；必填，同上 |
| `RUNTIME_RUN_CONTROL_SECRET` | 运行节点身份签名密钥；至少 32 字节，与运行控制一致 |
| `WORKER_ID` | 工作进程标识；默认随机生成，每个运行实例必须唯一 |
| `DEEPSEEK_API_KEY` | 模型接口密钥；启用时必填，禁用时允许空值 |
| `DEEPSEEK_BASE_URL` | 模型源站地址；默认 `https://api.deepseek.com`，启动入口强制 HTTPS（加密超文本传输协议） |
| `RUNTIME_MAX_TOOL_CALLS` | 每次运行工具调用上限；默认 100，范围 1–1000 |
| `RUNTIME_MODEL_MAX_RETRIES` | 同一失败请求最多额外尝试次数；默认 2，范围 0–5，0 关闭 |
| `RUNTIME_MODEL_RETRY_INITIAL_MS` | 初始退避毫秒；默认 500，范围 1–10000 |
| `RUNTIME_MODEL_RETRY_MAX_MS` | 最大退避毫秒；默认 10000，范围 1–10000，不得小于初始值 |
| `PORT` | 仅健康检查监听端口；默认 8080 |

模型名称来自 Catalog（定义中心）的授权版本；地址和凭据仅由运维配置，用户不能在聊天请求中指定。
默认定义中的模型名称、技能和权限应在启用前审查。程序不会自动加载 `.env`（环境配置文件）。
部署方式见 [部署说明](../dsh-agent-deploy/README.md)。

每个服务副本一次只运行一个子进程；扩大吞吐可增加副本，实际并发仍受运行控制全局上限约束（默认 64）。
这不是千用户容量承诺；公平调度、用户配额、排队长度和模型供应商限额仍待完善。
`/health/live`（存活检查）表示进程可响应；`/health/ready`（就绪检查）反映领取循环状态并返回是否启用，
不证明模型或所有工具可用。关闭状态可以健康，但不会消费任务。

停机中断当前子进程；续租失败也立即中断。终态提交失败最多重传三次同一结果，绝不重新调用模型。
无法确认终态时由运行控制租约过期机制收敛，不提供无限结果补偿；外部副作用可能已经发生。
运行器不发送“远程在途写入已经清空”的停止确认。取消后已通过最终授权的在途写入仍可能提交，
既有文件修改不回滚；这沿用工作区的明确撤销边界。

## 预算与安全边界

- 定义中的 `maxTurns`（最大步骤数）在这里限制模型请求步骤，而非用户聊天轮数；模型重试也消耗此预算。
- `maxOutputTokens`（最大输出词元数）限制单次模型请求，不是整次运行的总词元或费用配额；累计输出可能达到步骤数乘以单步上限，输入费用另计。
- `timeoutSeconds`（超时秒数）从取得输入后计算，并受运行控制总截止时间约束；默认约每 50 毫秒检查，同时在执行、工具与结果边界检查。
- 子进程的 V8（JavaScript 引擎）堆上限为 256 MiB（兆二进制字节），会话累计事件约 16 MiB 后中断；这不是操作系统总内存硬上限，容器另限 1 GiB（吉二进制字节）。
- 未注册 Bash（命令解释器）、本地文件、任意代码执行、动态插件加载或 MCP（模型上下文协议）连接能力。技能是已审核文本，不是用户上传的可执行代码。
- 父进程只持有工作节点身份密钥；不持有工作区能力签名密钥、在线授权签名密钥、数据库或对象存储密钥。
- 子进程不继承父进程完整环境，模型密钥仅通过进程间通信传入，不通过命令参数传入。子进程仍持有模型密钥，可信运行代码必须纳入供应链审查。
- 子进程隔离只用于生命周期与状态隔离，不是安全沙箱；同一操作系统用户下的进程没有严格互不可读保证。容器也不能替代所有威胁场景的强隔离。允许用户代码或第三方可执行插件前，必须重新设计执行沙箱与凭据边界。
- 工具输入输出均校验，依赖请求限制大小和时间且不跟随重定向；不向用户返回模型内部异常或子进程标准错误。

## 验证范围

先在根目录执行 `npm run build`（编译），再执行 `node --import tsx --test tests/runtime.test.ts`（运行测试）。
测试使用真实已发布 DSH 核心与官方模型适配器，但模型响应来自本机 SSE（服务器发送事件）模拟服务。
覆盖工具循环、技能和历史、子进程完成与取消、模型步骤上限、截断失败、续租丢失、定义超时、结果重传，
以及运行器—运行控制—工作区—会话—定义中心的真实 HTTP（超文本传输协议）调用闭环。
数据库使用 PGlite（轻量 PostgreSQL 引擎），文件对象使用内存替身；不代表真实模型、真实对象存储或生产集群验收。

## 逐次模型计量

执行入口在每次模型调用前等待运行控制确认开始记录，结束时上报 DSH 适配器返回的供应商计量。
父进程使用执行节点凭据转发；子进程只得到报告确认，不持有服务密钥。
工具中间步骤和最终回答都会计量，回答失败不抹除已上报的词元；同一流的多个用量快照不会重复累加。
缺失、无效或进程强杀导致的计量不被伪造为零；不保证取消后的最终报告必然送达。
报告重传不重跑模型。暂时性模型故障可在预算内原生重试，没有自动启用执行或计费逻辑。
详见 [模型用量说明](../docs/model-usage.zh-CN.md)。

## 顺序工作流执行

有工作流定义时，每次运行创建一个子进程，子进程一次调用 DSH 原生工作流引擎；DSH 负责条件与步骤衔接，每步使用独立插件上下文和工具子集。
最近成功输出作为历史数据传入；全流程共用原运行截止时间、工具次数上限和连续用量编号。
仅重传状态/结果报告，不重新执行已完成的模型步骤。进程退出不代表支持断点续跑，也不回滚已提交文件。
详见 [工作流协议与限制](../docs/workflow.zh-CN.md)。

## 多执行槽

`RUNTIME_CONCURRENCY`（单副本执行并发）默认 1，范围 1–16。每槽一次领取一个运行，没有额外预取队列。
每次执行仍启动独立子进程，保持身份、租约、工具与计费边界；停机取消并等待所有槽位清理，不自动重跑模型。
加槽前核对容器内存、供应商限额、调度与配额容量。上限 16 不是内存足够的保证，默认模板仍关闭执行器。
详见 [高并发说明](../docs/high-concurrency.zh-CN.md)。
