# dsh-agent-audit：平台审计服务

独立服务，拥有 PostgreSQL（关系型数据库）中的 `audit`（审计）模式。
当前覆盖运行接受/领取/终态、会话创建/修改、消息接受/助手投影、工作区创建和文件成功写入/删除。
尚未覆盖身份变更、目录列举、文件读取、失败请求及全部拒绝事件。

## 数据与可靠性

运行控制、会话和工作区分别在自己的业务事务内写入 Outbox（事务发件箱），独立后台循环通过 HTTP（超文本传输协议）投递。
网络投递不占用运行行锁，也不阻塞模型调用；故障保留消息，按 1–60 秒退避重试。
本地事务发件箱与运行状态同成同败；本地数据库异常仍会使业务事务失败。
这是原架构中消息总线方案的首版实现调整：独立发件箱直接投递，避免依赖公共短保留事件流做合规记录。
协议与数据所有权不变，将来可替换传输而无需让审计访问运行数据库。

审计按生产者分别校验结构，保存事件标识、时间、主体和资源标识、动作；会话修改可含修订号和归档状态，
文件变更可含前后版本及字节数。没有记录文件路径，所以不能靠本服务恢复文件名、内容或历史版本。
严格白名单拒绝额外字段，不保存提示词、回答、文件正文、工具参数、身份令牌或模型密钥。
同一事件标识且正文相同可重复提交，不同正文返回冲突；跨服务提交成功而确认丢失不会产生重复记录。
查询按当前用户和租户限制，采用事件标识游标；记录异步到达，不承诺即时可见或物理入库顺序。

数据库触发器拒绝更新、删除和清空记录。部署使用 `audit_writer`（审计写入账号）运行服务，
仅授予模式使用和表读取/插入权限；`audit`（审计管理账号）只执行迁移。
在线账号不能修改表结构、禁用触发器或跨服务读取数据。
数据库所有者与超级用户仍可绕过保护，这不是 WORM（一次写入多次读取）存储或密码学不可篡改证明。
长期保留、按时间分区、外部归档、管理员合规导出、异常检测和脱敏策略扩展尚待实现。

## 配置与接口

| 环境变量 | 含义 |
| --- | --- |
| `DATABASE_URL` | 在线使用审计写入账号，迁移使用独立管理账号 |
| `API_AUDIT_SECRET` | 聚合服务本人查询密钥，至少 32 字节 |
| `RUN_CONTROL_AUDIT_SECRET` | 运行控制写入密钥 |
| `CHAT_AUDIT_SECRET` | 会话服务写入密钥 |
| `WORKSPACE_AUDIT_SECRET` | 工作区服务写入密钥；全部写入密钥与查询密钥必须不同 |
| `PORT` | 服务端口，默认 8080 |

`POST /control/v1/records`（提交审计记录）接受上述三个独立生产者凭据，事件的生产者必须与凭据签发者一致；
`GET /internal/v1/audit`（读取本人审计）仅接受聚合服务凭据，外部入口为 `GET /api/v1/audit`。
英文 HTTP 方法 POST 和 GET 分别表示提交和读取。
结构见 [内部支撑协议](../dsh-agent-contracts/support-openapi.json)。
部署见 [部署说明](../dsh-agent-deploy/README.md)，当前要求第二版迁移，通过 `node dist/migrate.js`（迁移命令）顺序执行。
第二版允许非运行事件不带运行标识；旧记录不变，在线账号仍然不能更新或删除审计。

审计暂不依赖其他服务提供授权，亦不参与主请求授权决策。故障时运行可以继续，但审计发件箱会增长；
需监控积压与数据库容量，不能将“异步”理解为允许无界丢弃审计。
