# DSH 原生工作流接入

自 2026-09-29 起，工作流使用官方 `@deepseek-ai/dsh-workflow`（工作流接口）、
`@deepseek-ai/dsh-workflow-worker-thread`（工作线程执行引擎）及 `@deepseek-ai/dsh-subagent`（子智能体接口），固定版本均为 `0.1.1-rc.2`。
平台不再向执行器分配“下一步”，不再判断流程条件。

平台目前提供的预置模板支持顺序模型步骤及条件跳过，不开放任意图编辑。DSH 原生引擎有更多能力，但不等于平台已全部开放。
沿用已有用户隔离、不可变定义、运行租约、配额和受限工具，不引入新服务或用户可执行代码。

## 服务职责

| 项目 | 工作流职责 |
| --- | --- |
| `dsh-agent-catalog`（定义中心） | 管理员发布不可变工作流版本，验证步骤标识、总预算、工具子集及指令长度；按租户授权 |
| `dsh-agent-chat`（会话服务） | 沿用会话的精确定义版本绑定；只接收最终助手答复，不保存每个中间步骤为聊天消息 |
| `dsh-agent-run-control`（运行控制服务） | 冻结输入，接收 DSH 步骤状态与中间结果；校验租约、工具权限、预算及报告一致性，提供本人进度查询 |
| `dsh-agent-runtime-dsh`（DSH 执行服务） | 一次调用原生工作流引擎；提供受限子智能体、计量与工具适配，桥接 DSH 进度和最终结果 |
| `dsh-agent-quota`（配额服务） | 沿用一次运行的总输出预算预留和实际用量统计，不为每个步骤重新预留 |
| `dsh-agent-api`（前端聚合服务） | 验证用户身份，代理本人工作流进度；不判断条件、不持有执行凭据 |
| `dsh-agent-workspace`（工作区服务） | 沿用运行能力令牌和在线授权；运行控制进一步核对当前活动步骤的工具子集 |

各服务仍只通过协议合作，不跨服务查询数据库。DSH 拥有流程执行状态；数据库中的步骤表是状态投影，不是驱动引擎。
此轮未增加前端或步骤专用审计事件；已有实时事件增加步骤状态通知。

## 原生引擎与平台适配

运行器调用 `ctx.workflowEngine.start()`（启动工作流），并等待 `run.result`（执行结果），结束时调用 `run.dispose()`（释放资源）。
引擎在 Worker Thread（工作线程）中执行固定受审核脚本。脚本调用原生 `agent()`（启动子智能体），并自行决定步骤顺序和条件跳过。
原有 `workflow.steps`（步骤配置）仅作为脚本的 `args`（输入参数），不是另一套服务端状态机。

`platform-preset`（平台预置子智能体适配器）通过原生子智能体接口注册：按冻结定义创建受限 DSH 智能体，
桥接现有工具、计量、进度与取消信号，不返回“下一步”命令。
每步使用独立的 Cordis Context（插件容器上下文），全工作流在同一个运行子进程内；不是每步启动一个进程。
父智能体只为原生接口提供生命周期归属，不额外调用模型。

官方工作线程内的 `node:vm`（节点虚拟机上下文）不是安全沙箱。因此脚本是部署代码中的固定模板，
用户提示词、步骤指令和模型输出只作为数据传递，绝不拼接进脚本。
没有向模型注册 `tool-workflow`（任意脚本工作流工具），也没有开放用户脚本、动态插件或本地文件权限。
以后增加模板，应在受审核部署代码中扩展；开放任意脚本前必须重新设计安全隔离，不能仅靠目录钩子。

## 定义规则

定义中的可选 `workflow.steps`（工作流步骤列表）按数组顺序执行，最多八步：

| 字段 | 中文含义及约束 |
| --- | --- |
| `id` | 步骤标识，在该版本内唯一 |
| `instructions` | 管理员审核的步骤指令，最多 4000 字符；与主提示词组合后保持原提示词长度限制 |
| `maxTurns` | 当前步骤的最大模型请求次数，包括工具循环中的模型请求 |
| `tools` | 当前步骤可用工具，必须是顶层工具名单子集；空数组表示不允许工具 |
| `whenPreviousContains` | 可选条件：最近成功步骤输出包含指定字面文本才执行，否则跳过 |

第一步不能带条件，因此总能有一个执行步骤。固定原生脚本用大小写敏感的字面文本包含判断，不解释用户提供的表达式。
跳过的步骤不消耗模型调用，也不改变“最近成功输出”。所有步骤最大模型请求数之和不能超过运行总上限。
步骤不能选择新的模型、扩展工具权限、覆盖用户身份或新增工作区；全程沿用冻结版本的模型及技能。

条件依赖模型输出，只适合业务路由，不能充当授权、合规审批或支付确认。
用户资料可能影响模型输出，因此即使条件满足，也不能突破服务端权限与预算边界。

## 执行与失败语义

1. 运行按原链路领取、预留总预算并冻结输入。
2. 执行器创建一次运行子进程，调用 DSH 原生引擎。DSH 执行固定脚本，决定启动或跳过哪个步骤。
3. 子智能体适配器在模型调用前等待步骤开始状态被平台确认；只注册该步工具。最近成功输出作为历史数据传入，不拼接进系统指令。跳过通知由原生脚本发出，经进度通道持久保存。
4. 模型用量沿用全运行连续调用编号，并在运行控制保存所属步骤；当前步骤不能超额或越序调用。
5. 步骤结果只有在至少一次模型调用且所有已开始调用的最终计量报告到达后才能提交。计量未知仍可完成报告，不等于零消耗。
6. 全部步骤成功或已跳过后，运行才可成功；最终回答必须等于最后成功步骤的输出，再通过原可靠投影写回会话。

所有步骤状态经已有进度接口按全运行序号幂等重传；相同序号内容不同则冲突。下一模型调用等待必要状态确认；报告失败则停止，确认丢失不会重新调用已完成步骤的模型。
工具调用数上限、运行总截止时间及定义超时覆盖整个工作流，不在步骤切换时重置。
输出预留仍为“顶层最大模型请求数 × 单次最大输出词元数”；条件跳过或少用预算不会自动退款。

任何步骤失败或运行取消后停止推进；已完成的文件写入不会回滚。
持久步骤记录用于查看进度、工具授权和计量关联，不代表 DSH 原生检查点或进程崩溃后的自动续跑。
当前没有自动恢复、人工重试或副作用补偿；崩溃后沿用租约到期失败处理，不能把状态重置后直接重跑。
取消后的在途工具提交窗口仍存在，工作流没有增强为跨服务原子撤销。

步骤之间传递原始会话历史、当前用户任务及最近一个成功步骤的文本结果，不累积传递所有中间结果。
平台不按消息条数或总字符数裁剪步骤历史；上下文压力与摘要交给 DSH 原生插件，摘要也消耗步骤预算。
当前仍是文本记录导入，不是跨轮原生会话恢复；详见 [原生上下文说明](native-context.zh-CN.md)。

## 接口与状态

公共接口：`GET /api/v1/runs/{runId}/workflow`（读取本人运行工作流进度）。
返回运行状态、是否已加载工作流以及步骤标识、状态、时间；不返回中间输出、工具参数或步骤指令。
其他用户或租户查询返回未找到；客户端不能覆盖身份。未冻结输入时工作流尚未加载，`enabled=false` 不代表定义一定没有工作流。

| 状态 | 中文含义 |
| --- | --- |
| `pending` | 尚未进入，不表示终态运行将来还会执行 |
| `running` | 已进入、等待步骤结果 |
| `succeeded` | 步骤结果已持久保存 |
| `skipped` | DSH 判定条件不满足，平台已记录跳过 |
| `interrupted` | 运行已失败或取消，原活动步骤未成功完成 |

内部统一使用 `POST /worker/v1/runs/{runId}/progress`（上报进度），报告新增 `kind: workflow`（工作流类型）：
步骤标识、`running`（运行中）／`skipped`（已跳过）／`succeeded`（成功）状态；仅成功报告包含输出。
服务器只验证已批准步骤、有效租约、无重叠活动步骤及计量终报，不执行条件、不分配下一步。
完整输出只保存在内部步骤记录，不复制到公共状态事件；正文预览仍使用已有授权事件通道，不能将中间正文视为保密于本人。

公共 `run.status.v1`（运行状态事件）新增 `phase: workflow`（工作流阶段）以及 `stepId`（步骤标识）、
`stepState`（步骤状态）。公共进度查询继续使用原路径。

旧 `/workflow/next`（申请下一步）与 `/workflow/result`（提交步骤结果）内部接口已删除。
内部接口仅接受执行节点凭据，不通过公网网关暴露；取消后包括重复进度报告在内均拒绝接收。

## 发布和升级

提供 [只读文档审阅示例](../dsh-agent-catalog/definitions/document-review-workflow.v1.json)。
`configure-model`（待配置模型）是占位值，须替换为账号批准且可用的模型；示例未自动发布，也未切换租户默认定义。
替换后由管理员使用定义中心管理数据库连接执行：

```powershell
npm run publish -w @dsh-agent/catalog -- --file definitions/document-review-workflow.v1.json --tenant your-tenant --default
```

`your-tenant`（目标租户）须替换为真实授权租户；`--default`（设为默认）会影响之后创建的会话，只在确认切换时使用。
旧会话保持原版本，不能通过覆盖原有版本内容升级；定义变更必须发布新版本。

升级前暂停领取和入口写入，等待在途任务结束或明确取消，再停止旧执行器并备份数据库。
本次不新增数据库迁移；基线必须已应用步骤表的第 5 版迁移和进度通道的第 7 版迁移。
执行 `npm ci`（按锁文件安装依赖）、`npm run check`（类型、构建与测试检查）。
协调升级协议消费者、运行控制和执行器后再恢复领取；新旧内部协议不兼容，不可混跑。
已有步骤定义无需改写，不更改已发布不可变版本；原无工作流定义仍按普通智能体运行。
执行器仍默认关闭，本次不自动启用真实模型或积分计费。

尚不支持 DAG（有向无环图）的任意依赖、并行分支、循环、人工审批、定时触发、自动恢复、跨步骤补偿或可视化编辑。
原生数据库多连接竞争、真实模型和集群验收仍需部署环境；本机模拟模型测试不等于生产上线。
