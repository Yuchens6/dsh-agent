## 1. 项目定位与技术栈

本项目在 DSH（DeepSeek Harness，DeepSeek 智能体执行框架）外构建多租户后端平台。用户通过网页提交任务，平台负责身份、文件权限、排队执行、过程反馈、用量和积分管理。DSH 提供模型循环等执行能力，不直接承担整个平台的用户管理和安全隔离。

这里的 Tenant（租户）表示公司或组织；User（用户）表示组织内个人。资源主体使用 `tenantId + uid`（租户标识与用户标识）联合确定。公司拥有积分不代表所有员工可以共同消耗任意额度，员工使用独立分配的账户。

| 技术或组件 | 当前用途 |
| --- | --- |
| TypeScript（带类型的 JavaScript）、Node.js（脚本运行环境）24+ | 后端业务和执行服务 |
| npm workspaces（包工作区） | 单仓库中的独立包构建、依赖和测试 |
| Fastify（网页服务框架）、Zod（数据结构校验库）、jose（令牌密码学库） | 服务接口、输入校验、凭证验证 |
| PostgreSQL（关系型数据库） | 业务记录、任务、事务发件箱、积分账本；按服务分数据库模式和账号 |
| NATS JetStream（持久化消息流） | 运行请求投递与公开事件重放 |
| S3（简单存储服务）兼容对象存储 | 工作区文件正文；SeaweedFS（分布式文件与对象存储）是已部署并验证的本机实现 |
| Keycloak（身份与访问管理平台） | 用户登录及身份令牌签发 |
| Envoy Gateway（边缘网关控制器）、Kubernetes Gateway API（容器平台网关接口规范） | 集群入口、路由、加密与流量策略 |
| PGlite（轻量 PostgreSQL 引擎） | 自动测试中的数据库执行环境，不是生产数据库 |

仓库包含十二个可构建的包：一个协议包、十个后端服务包和一个网页服务包。`dsh-agent-edge`、`dsh-agent-iam`、`dsh-agent-deploy` 是网关、身份与部署配置项目，不是额外三个自研业务进程。目前不依赖 Redis（内存数据存储）。

执行服务组合固定版本的已发布上游核心包：DSH `0.1.1-rc.2`、Cordis（插件生命周期容器）`4.0.1`。没有修改上游源码，也不是用 SDK（软件开发工具包）直接驱动默认全功能演示服务器。根目录的 `deepseek-harness/` 为独立上游检出，不是平台运行时的本地源码依赖。依赖锁定以 [package-lock.json（依赖锁文件）](../package-lock.json) 为准。

## 2. 架构与项目职责

下面只展示主要链路；内部授权、配额与审计调用见职责表和后文。

```text
浏览器（工作台已实现并在本机启用）
  ├─ 业务请求 → Edge 边缘网关 → API 前端聚合服务
  │                              └→ Chat 会话服务 → 本库事务发件箱
  │                                                     ↓
  │                                              NATS 持久运行请求
  │                                                     ↓
  │                                              Run Control 运行控制
  │                                                     ↑ 领取、续租、结果
  │                                              Runtime DSH 执行服务
  │                                                     ↓ 受限工具
  │                                              Workspace 工作区服务
  │                                                     ↓
  │                                              PostgreSQL 元数据 + S3 正文
  └─ 事件连接 → Edge 边缘网关 → Stream 事件服务 ← NATS 公开事件

最终回答：Runtime → Run Control 持久结果 → Chat 助手历史 → 完成事件
```

| 项目名与中文职责 | 持有的数据/配置 | 明确不负责 |
| --- | --- | --- |
| `dsh-agent-edge`：边缘网关 | 公共路由、TLS（传输层安全）、粗粒度认证、限流、来源策略和网络策略 | 业务编排、积分结算、运行器公网访问 |
| `dsh-agent-api`：BFF（面向前端的后端） | 身份验证、输入验证、内部调用、错误映射、单副本入口容量 | 不持有业务数据库，不决定文件归属或价格 |
| `dsh-agent-iam`：IAM（身份与访问管理）配置 | Keycloak 身份域、登录客户端和令牌声明映射 | 尚未实现公司成员、邀请、角色管理和切换租户的完整业务 |
| `dsh-agent-chat`：会话服务 | 会话、消息、绑定工作区与定义版本、幂等记录、事务发件箱 | 模型执行、文件正文、积分账本 |
| `dsh-agent-stream`：事件流服务 | 临时订阅连接、事件白名单、重放游标与背压控制 | 不读业务数据库、不直接连接执行子进程 |
| `dsh-agent-workspace`：工作区服务 | 工作区归属、文件版本、上传票据、容量、对象回收；独占对象存储访问凭据 | 宿主机共享目录、任意命令或任意网络工具 |
| `dsh-agent-catalog`：定义中心 | 不可变智能体版本、租户授权、默认版本、受控发布和撤销 | 模型执行、在线用户上传插件、发布审批界面 |
| `dsh-agent-run-control`：运行控制服务 | 持久任务、调度、租约、输入快照、工作流状态、进度、结果、投影与支撑发件箱 | 模型协议实现、对象正文存取、计价计算 |
| `dsh-agent-runtime-dsh`：DSH 执行服务 | 执行槽、每次运行子进程、原生工作流调用、模型适配器、工具转发、用量上报 | 不访问业务数据库，不持有 S3 密钥，不允许模型选择用户身份 |
| `dsh-agent-quota`：配额与积分服务 | 并发与日预算、调用用量、价格版本、公司/员工积分、冻结、结算与流水 | 支付渠道、供应商正式账单对账、模型调用 |
| `dsh-agent-audit`：审计服务 | 白名单元数据事件、去重、追加写保护、本人查询 | 不保存提示词、回答、文件正文或密钥；不代替授权服务 |
| `dsh-agent-knowledge`：知识访问服务 | PostgreSQL 全文/结构化/纯图谱/无向量混合检索及 LightRAG（图谱检索增强生成服务）适配；固定源、精确用户授权、独立运行能力 | 管理员离线发布语料；不开放任意查询、用户图谱写入或自动文件同步；部署待验收 |
| `dsh-agent-contracts`：公共协议包 | 请求/响应/事件校验及 OpenAPI（开放接口描述规范） | 不保存业务数据、不实现跨服务业务规则 |
| `dsh-agent-deploy`：部署工程 | 容器构建、数据库账号、迁移任务、集群清单、监控模板、原生基础设施脚本初版 | 不意味着所有部署方式已经运行验收 |

低耦合约定：每个服务只访问自己的数据库模式；业务数据通过已认证的 HTTP（超文本传输协议）接口或消息协议交换；不能导入另一服务的内部实现。共享协议不等于共享数据库。调用边使用独立凭据，读取模型定义、写文件、结算积分各有唯一的权威服务。

## 3. 一次对话的完整过程

1. 用户经 Keycloak 登录，浏览器取得 JWT（JSON 网络令牌）。聚合服务验证签名、签发者、受众、有效期和身份声明，不采信浏览器自填的身份请求头。
2. 创建会话时，会话服务通过工作区服务获得该主体的工作区，通过定义中心获得租户默认版本，保存精确绑定。之后切换默认定义不会修改已有会话。
3. 用户带 `Idempotency-Key`（幂等键）提交消息。会话服务在一次数据库事务中保存消息、公开事件、独立运行请求及变更审计；成功后返回 `202`（已接受），不等待模型输出。
4. 后台从 Outbox（事务发件箱）投递到 NATS。运行控制消费请求，以 Inbox（事务收件箱）去重，并持久保存排队任务。
5. 执行器领取任务。运行控制检查全局、租户、用户和同会话并发条件，发放 Lease（执行租约）。同会话前一回答尚未投影完成时，下一轮不能启动。
6. 首次取得输入前，运行控制完成配额预留，获取授权的完整聊天记录与精确定义并冻结快照；有积分计费时同时冻结价格快照与预算。Chat 不按轮数／总字符数裁剪模型上下文，Runtime 按原始角色导入原生 Session（会话），由 DSH 的 Compaction（上下文压缩）插件管理。摘要同样计量；跨轮原生日志恢复尚未实现，见 [上下文说明](native-context.zh-CN.md)。外部依赖调用后重新检查运行状态。
7. 执行器为整次运行创建一个受控 DSH 子进程；有工作流时一次调用 DSH 原生引擎，由其工作线程决定条件和步骤衔接，每步在独立插件上下文中执行。平台只桥接获准输入、状态、计量和工具调用。模型只能请求已注册的工具，父进程申请短期能力并转发。
8. 模型调用开始、正文预览、工具状态、调用用量分别通过内部协议上报。运行控制验证租约、顺序与限额，持久保存后再发布公开事件。
9. 执行器提交终态和完整输出。成功回答经可靠 Projection（结果投影）写回会话，投影确认后才发布最终快照与完成事件。
10. 配额关闭、计量结算和审计投递走持久重试。运行结束与账本查询可能暂时不同步，不能把待报用量当作零。

“同一次消息提交成功”不等于“模型已启动”，更不等于“回答成功”。运行仍有效时，模型暂时性错误使用 DSH 原生插件默认额外重试至多 2 次，受原调用预算和截止时间约束；失败草稿按调用编号隔离。租约过期或整个运行失败后不会自动重跑任务和文件副作用；结果确认丢失只重传同一结果。取消不会回滚已经提交的文件。见 [模型重试设计](model-retry.zh-CN.md)。

## 4. 身份、工作区与权限隔离

### 4.1 身份边界

本地 Keycloak 使用固定租户 `local-dev`，访问令牌的 `sub`（主体）映射用户标识。服务逻辑支持按动态租户隔离，但当前身份配置还不是完整的公司成员管理系统。

用户登录使用 Authorization Code（授权码）与 PKCE（代码交换证明）流程；没有启用密码授权。前端访问 `http://localhost:3000`，登录回调配置为 `http://localhost:3000/callback`，不使用通配回调。

内部服务使用独立签名凭据，不能用一把密钥横跨所有调用。执行器身份凭据、短期工作区能力令牌、用户令牌和订阅凭证不可互换。

### 4.2 工作区不是宿主机目录

每个 `tenantId + uid` 唯一分配一个逻辑工作区，展示目录名为 `uid`，实际标识为 `workspaceId`（工作区标识）。文件正文按工作区和版本标识存储为对象，用户路径只进入受限的虚拟路径模型，不解析为 Windows 或 Linux（类 Unix 操作系统）路径。

| 约束 | 当前实现 |
| --- | --- |
| 文件类型 | UTF-8（统一字符编码）文本；不支持任意二进制 |
| 文件大小/数量 | 单文件 64 KiB（千二进制字节）；当前文件合计 16 MiB（兆二进制字节）、最多 1024 个 |
| 在途上传 | 最多 16 个、合计 1 MiB 的预留 |
| 路径 | 规范化相对路径；拒绝绝对路径、盘符、反斜线、点段、百分号、控制字符等 |
| 版本 | `expectedVersion`（预期版本）为空只允许新建；覆盖/删除必须匹配现有版本 |
| 资源隐藏 | 他人资源与不存在资源统一返回 `404`（未找到） |
| 暂不支持 | 大文件、空目录、重命名、历史版本下载或恢复 |

写入先保存上传票据，再创建不可覆盖对象，最后锁定工作区、复核版本和权限并切换当前引用。竞争失败不覆盖已有内容。旧对象和未提交对象由 GC（垃圾回收）处理；文件逻辑额度不是物理磁盘占用的硬上限。

### 4.3 执行器只能使用授权工具

| 内部工具名 | 模型侧名称 | 能力 |
| --- | --- | --- |
| `workspace.list` | `workspace_list` | 分页列出虚拟文件 |
| `workspace.read` | `workspace_read` | 读取文本与版本 |
| `workspace.write` | `workspace_write` | 按预期版本创建或覆盖文本 |
| `knowledge.search` | `knowledge_search` | 显式授权知识源的可配置无向量检索或 LightRAG 检索；可选，旧定义不自动获得 |

执行工具入口是 `POST /execution/v1/tools`，不经公网网关。请求不能指定用户、租户或工作区。Capability（能力令牌）最长 30 秒，且受租约与运行截止时间约束；工作区服务每次在线向运行控制核验绑定与当前工具权限，授权服务不可达时拒绝操作。

知识工具使用知识服务上的同名内部路径，但能力受众、签名密钥、授权查询均与工作区独立；定义必须声明 `knowledgeSources`（允许知识源），知识服务还须检查该源明确允许的租户/用户。源指向本服务 PostgreSQL 审核语料或 LightRAG 独立端点，整库授权，不提供逐文档权限。管理员配置 `ragMode`（检索模式），请求 `mode` 仅控制 LightRAG，不能覆盖模式。详见 [无向量检索](nonvector-rag.zh-CN.md) 与 [LightRAG 接入](lightrag-integration.zh-CN.md)。

没有执行器文件删除工具，也没有 Bash（命令解释器）、宿主文件系统、任意代码、动态第三方插件或 MCP（模型上下文协议）连接入口。Skills（技能）是已审核文本，不是用户可执行代码。

这套安全边界允许共享执行服务池，无需一用户一个 Pod（容器工作负载实例），但前提是继续维持受限能力集合。子进程不是操作系统安全沙箱；同一系统账号下的进程不具备严格互不可读保证。若增加用户代码或第三方可执行插件，必须重新设计沙箱、凭据和网络隔离，不能只加路径检查 Hook（拦截钩子）。

**取消不是强原子撤销：** 最后一次在线授权和工作区提交之间仍有跨服务窗口，已获最终授权的在途写入可能在取消返回后完成。当前没有在途操作清空确认协议，不承诺“取消返回后绝无提交”。

## 5. 智能体定义、工具、技能与工作流

Agent Definition（智能体定义）相当于平台受控的 Agent Preset（智能体预设）：包含标识、版本、系统提示词、模型、工具白名单、技能文本和预算。它是经过审核的配置，不是用户任意提交的运行环境。

技能已接入 DSH 官方注册表和加载器，不再把全部正文直接拼入系统提示词。模型通过原生目录按需调用 `skill`（技能工具），用户也可在聊天中写 `/技能名`；原生调用策略分别控制模型和用户途径。平台提供批准的固定内容与共享预算，不扫描文件系统、不执行技能脚本。配置、行为变化和能力复用边界见 [原生技能说明](native-skills.zh-CN.md)。跨轮原生会话持久化仍未完成。

定义中心默认账号 `catalog_reader`（定义只读账号）保持只读；管理员命令行发布与迁移使用 `catalog`（定义管理账号）。工作台可另配写池，仅让租户管理员受限派生发布；详见[工作台权限](agent-studio.zh-CN.md)。同版本同内容允许重放，不同内容冲突；已发布定义不可变。租户授权可受控撤销，冻结输入不会被追溯撤销，停止在途执行需取消运行。

Workflow（工作流）已接入 DSH 原生引擎，平台当前开放的预置模板支持最多八个顺序步骤及字面文本条件跳过：

| 字段 | 中文含义和规则 |
| --- | --- |
| `workflow.steps` | 顺序步骤数组；无此字段时为原单步模式 |
| `id`、`instructions` | 唯一步骤标识、已审核步骤指令 |
| `maxTurns` | 本步骤最大模型请求次数；各步之和不能超过定义总上限 |
| `tools` | 当前步骤工具，必须是顶层工具白名单子集 |
| `whenPreviousContains` | 最近成功输出包含指定字面文本才执行；第一步不能带条件 |

工作流调用 DSH 原生工作线程引擎，由固定受审核脚本决定条件和步骤衔接；运行控制只保存状态投影并校验租约、权限、预算和计量。跳过不消耗模型调用、不改变最近成功结果；最后成功步骤输出作为最终答案。总截止时间、工具次数和调用编号跨步骤累计，不在换步时清零。

条件不能当作权限、合规审批或支付确认。持久进度不等于支持崩溃续跑；当前不支持 DAG（有向无环图）、并行分支、循环、人工审批、自动恢复和副作用补偿。

新增能力的正确入口：先修改公共协议与定义校验，再实现服务端授权和受限工具，最后在运行器注册并增加隔离测试。不能只让提示词“禁止越权”，也不能通过定义字段绕过工具白名单。工作流示例和受控发布方法见 [工作流说明](workflow.zh-CN.md)。

<a id="streaming"></a>
## 6. 实时反馈与客户端接入

当前已实现 SSE（服务器发送事件）后端协议，未实现网页客户端。状态提示与实际模型正文分开：排队不冒充“模型思考中”，不公开模型内部推理。

| 信号 | 中文含义与建议界面 |
| --- | --- |
| 请求未确认 | 客户端本地显示“正在发送” |
| HTTP `202` | 已持久接收，显示“已接收，等待处理” |
| `run.status.v1` + `queued` | 运行已接纳，显示“正在排队” |
| 同上 + `preparing` | 已领取，显示“正在准备上下文” |
| 同上 + `waiting_model` | 调用开始已记账，准备请求模型；不保证供应商已接受 |
| 同上 + `tool` | 即将操作受限工具，不表示已经成功执行 |
| `run.output.preview.v1` | 临时正文预览，不是最终成功答案 |
| `run.output.snapshot.v1` | 最终输出快照；**替换**整个预览，不能追加 |
| 失败/取消事件 | 停止加载，保留预览时标注未完成 |

首个完整正文片段立即上报，此后按 75 毫秒或 2048 个 UTF-16（16 位统一字符编码）代码单元合并。公开事件空闲发布间隔为 100–124 毫秒；执行器空闲领取仍为 1–1.25 秒。这些是内部策略，不是端到端延迟承诺。

每运行最多 4096 条执行器进度、累计 1 MiB 预览文本。持久确认失败重传同序号，最多三次，不重跑模型。进度也受租约、取消和当前工作流步骤约束。

客户端接入顺序：

1. 申请会话订阅凭证，使用支持自定义请求头的 `fetch`（浏览器请求接口）连接 `/events/v1/sessions/{sessionId}`。携带用户令牌和 `X-Session-Capability`（会话订阅能力凭证），不把令牌放查询字符串。
2. 提交消息后直接根据 `202` 更新接收状态，不等待事件到达才反馈。
3. 事件按 `eventId`（事件标识）去重；预览按运行、尝试、调用分组，工作流另区分步骤。进度序号可能因工具状态出现空洞，不代表正文丢失。
4. 最终快照覆盖预览。如果快照 `text`（正文）为 `null`（空值），调用本人运行查询获取 `output`（完整输出）；这是大结果降级，不代表空答案。
5. 新客户端忽略旧的 `run.output.delta.v1`（最终结果兼容分块），避免把兼容分块和预览重复拼接。
6. 保存 `Last-Event-ID`（最后事件游标），重新取得凭证后恢复连接。凭证最长约 60 秒，重连需随机抖动；游标过期返回 `409 CURSOR_EXPIRED`（游标已过期），重新查询历史与运行状态。

事件服务默认每实例 1000 个连接，20 秒心跳，写缓冲持续阻塞 5 秒断开慢消费者。原生 `EventSource`（浏览器事件源）不能直接满足自定义认证头要求。模型正文必须作为不可信文本处理，不能直接执行为 HTML（超文本标记语言）。完整兼容规则见 [实时反馈说明](realtime-feedback.zh-CN.md)。

## 7. 配额、用量与积分

Quota（配额）包含并发和每日保守输出预算；Usage（用量）记录每次模型调用的供应商计量；Points（积分）将已报告用量按平台价格折算为账户扣减。三者不是同一概念。

公司发放 100 积分、分给五人各 20 后，公司未分配余额为零，员工分别拥有 20；不能自动借用他人账户或其他运行的冻结额。

计价过程：普通输入、缓存命中、输出词元分别乘对应每百万词元单价，得到 CNY（人民币）金额，再乘配置的每元积分数。每次调用分别向上取整到六位小数，然后累加；推理词元已包含在输出时不重复计费。使用 BigInt（大整数）定点计算和十进制字符串，避免浮点误差。

运行前冻结价格版本、兑换比例与 `reservePointsPerRun`（单次冻结积分）。之后调价不重算历史；每个运行/尝试/调用唯一结算，重复报告不重复扣费。关闭报告携带调用总数，只有相关调用全部报告并结清才释放剩余冻结积分。

未知计量保留 `pending_usage`（用量缺失待结算），余额不足保留 `pending_balance`（余额不足待结算）。它们不是零费用；失败或取消也不抹除已发生费用。单次冻结额不是供应商费用硬上限。每日保守预算和积分剩余额度释放规则不同，不能混为“全部退款”。

`POINTS_BILLING_ENABLED`（积分计费开关）默认关闭。启用前须执行配额第三版迁移、发布真实适用的价格、发放公司积分并分配员工账户。受控管理命令支持价格发布、公司发放、员工分配和已有数据重新结算；没有支付充值、退款、离职回收、缺失计量补录或管理员自助界面。

完整公式、配置字段和操作示例见 [积分计费说明](points-billing.zh-CN.md)；供应商用量报告不等于已核对正式账单，示例价格不得视为真实报价。

## 8. 公开接口索引

方法中文对照：`GET` 读取、`POST` 提交、`PATCH` 局部修改、`PUT` 写入、`DELETE` 删除。下面路径中的花括号表示标识参数。完整字段以 [公开 OpenAPI](../dsh-agent-contracts/openapi.json) 为准。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/v1/me` | 当前认证主体 |
| `GET/POST /api/v1/sessions` | 列会话 / 创建会话 |
| `GET/PATCH /api/v1/sessions/{sessionId}` | 会话详情 / 带修订号改标题或归档状态 |
| `POST /api/v1/sessions/{sessionId}/messages` | 幂等接收消息，成功返回 202 |
| `GET /api/v1/sessions/{sessionId}/history` | 分页历史 |
| `POST /api/v1/sessions/{sessionId}/subscription` | 申请短期订阅能力 |
| `GET /events/v1/sessions/{sessionId}` | 双凭据事件流 |
| `POST /api/v1/workspaces/ensure` | 分配/获取当前主体工作区 |
| `GET /api/v1/workspaces/{workspaceId}` | 工作区概况 |
| `GET /api/v1/workspaces/{workspaceId}/files` | 分页文件列表 |
| `GET/PUT/DELETE /api/v1/workspaces/{workspaceId}/file` | 文本文件读取、条件写入与条件删除 |
| `GET /api/v1/definitions` | 已授权定义摘要 |
| `GET /api/v1/definitions/{id}/versions/{version}` | 已授权的精确定义版本 |
| `GET /api/v1/runs`、`GET /api/v1/runs/{runId}` | 本人运行列表、状态及结果 |
| `GET /api/v1/runs/{runId}/workflow` | 本人步骤进度，不返回中间输出和步骤指令 |
| `POST /api/v1/runs/{runId}/cancel` | 取消排队或活动任务 |
| `GET /api/v1/quota` | 本人配额 |
| `GET /api/v1/usage` | 按 UTC（协调世界时）日期查询本人模型用量 |
| `GET /api/v1/points`、`GET /api/v1/points/ledger` | 本人积分和分页流水 |
| `GET /api/v1/audit` | 本人审计元数据 |

创建会话、提交消息必须保留幂等键。响应丢失后重试同一正文和同一键，不要创建新键。分页通常使用 `limit`（页大小）与 `after`（上一页游标），不能要求无界返回全部记录。文件写入使用版本冲突协议，不等同于消息幂等协议。

`/worker/v1`（执行端接口）、`/execution/v1`（执行工具接口）、`/internal/v1`（内部业务接口）、`/control/v1`（支撑写入接口）以及 `/metrics`（指标接口）不应获得公网路由。浏览器的业务入口只有 `/api/v1` 和 `/events/v1`，身份登录由受控身份端点单独提供。

<a id="data"></a>
## 9. 数据所有权、迁移与一致性

本地组合部署使用一个 `agent` 数据库，但服务之间不是共享表。Schema（数据库模式）、账号和默认权限分开。生产是否拆到不同数据库实例属于部署选择，不能改变数据所有者和授权边界。

| 数据模式 | 在线账号 | 当前业务迁移版本 |
| --- | --- | --- |
| `chat`（会话） | `chat` | 5：接收门禁 |
| `workspace`（工作区） | `workspace` | 2：变更审计 |
| `catalog`（定义） | `catalog_reader`；管理使用 `catalog` | 1 |
| `run_control`（运行控制） | `run_control` | 7：实时进度 |
| `quota`（配额） | `quota` | 3：积分 |
| `audit`（审计） | `audit_writer`；迁移使用 `audit` | 2：多生产者 |
| `knowledge`（知识） | `knowledge_reader`；迁移和语料发布使用独立 `knowledge` 管理账号，按手册预先创建 | 1：语料、文档、结构化记录、实体及关系；仅无向量后端需要 |
| `iam`（身份） | `iam` | 由 Keycloak 管理，不使用上述业务迁移编号 |

初始化数据库账号不等于完成业务迁移。迁移入口在各服务 `src/migrate.ts`（迁移源文件），构建后通过 `dist/migrate.js`（迁移产物）执行；不能用只读账号执行迁移。迁移版本记录来自代码，不代表本机数据库已升级。

可靠性不是跨系统一次大事务，而是本地事务与幂等协议组合：

- 接收消息和发件箱一起提交；消息代理故障保留待发记录。
- 消费运行请求使用收件箱去重；投递确认丢失允许重传。
- 最终结果先保存，再投影助手历史；投影成功前阻塞同会话下一轮和成功完成事件。
- 文件正文上传与元数据提交之间用票据和回收补偿，不覆盖旧可见版本。
- 积分扣减、用量入库和流水在配额本库事务内一致；跨服务用量最终一致。
- 审计由会话、工作区和运行控制自己的发件箱通过认证 HTTP 投递，并非直接订阅公共短保留事件流。

审计目前只记录运行生命周期及成功的会话/文件变更，不记录完整读取、身份和拒绝事件。追加写账号与触发器不是对数据库超级用户的密码学防篡改保证。

升级应在维护窗口停止新写入和执行、处理在途任务、备份数据库，再按专题部署说明迁移并更新兼容服务。实时反馈需要运行控制第 7 版；积分开关与新旧运行控制协议不能不加协调地混用。

<a id="capacity"></a>
## 10. 并发控制与容量边界

系统把短请求接收、持久排队、受限执行、事件连接分开扩展。QPS（每秒请求数）、长连接数、排队任务数、同时模型调用数是不同指标，增加接入副本不等于增加供应商模型吞吐。

| 配置或限制 | 默认/范围 | 所属边界 |
| --- | --- | --- |
| `API_MAX_IN_FLIGHT`（入口在途数） | 128 | 单副本；满载返回 503 和建议重试时间 |
| `CHAT_MESSAGES_PER_MINUTE`（新消息频率） | 120 | 同租户用户跨会话、跨副本共用数据库计数 |
| `CHAT_PENDING_PER_USER` / `CHAT_PENDING_PER_SESSION`（未投递积压） | 1000 / 100 | 只限制会话服务尚未投递的运行请求 |
| `DB_POOL_MAX` / `DB_MAX_WAITING`（连接池 / 额外等待） | 10 / 64 | 会话、运行控制各自进程；不是数据库全局连接数 |
| `CHAT_PUBLISH_WORKERS`（发布并发） | 2，范围 1–8 | 不同会话并行，同会话顺序保持 |
| `RUN_DELIVERY_WORKERS`（支撑/投影并发） | 各 2，范围 1–8 | 后台网络等待也消耗数据库连接 |
| `RUN_MAX_ACTIVE`（全局活动运行） | 64 | 仍受租户、用户、配额和执行槽约束 |
| `RUN_TENANT_ACTIVE` / `RUN_USER_ACTIVE`（公司 / 用户并发） | 32 / 2 | 达到调度上限时保留排队 |
| `RUN_AGING_SECONDS`（等待老化阈值） | 60 秒 | 符合调度条件的老任务优先，不能越过权限或并发限制 |
| `RUNTIME_CONCURRENCY`（每副本执行槽） | 1，范围 1–16 | 无额外任务预取；需核算内存、模型限额和预算 |

重要限制：未投递积压上限不限制已经进入运行控制数据库的等待任务，尚无全链路硬容量协议。当前运行请求消费者只允许一个未确认消息，调度有全局短事务锁，配额预留按公司串行。单纯增加副本不能消除这些瓶颈。

历史合成负载记录（2026-09-26，不是完整模型链路）：

| 场景 | 成功接收 | 拒绝/错误 | 成功接收吞吐 |
| --- | --- | --- | --- |
| 1000 请求，32 个客户端在途 | 1000 | 无 | 245 条/秒 |
| 10000 请求，128 在途，入口 32 槽 | 1440 | 8560 个 503 | 200 条/秒 |
| 10000 请求，256 在途 | 4082 | 5870 个 503、48 个连接错误；未通过 | 263 条/秒 |

这些测试使用合成身份和 PGlite，没有完整身份系统、NATS、SSE 或模型链路。快速拒绝不能算有效处理吞吐，不能外推为一万 QPS 或一万人同时对话已达标。具体方法和失败证据见 [本机负载记录](load-test-results.zh-CN.md)。

## 11. 开发、配置与部署

### 11.1 开发与测试入口

在仓库根目录执行；需要 Node.js 24+ 和 npm（包管理工具）：

```powershell
npm ci
npm run typecheck
npm run build
npm test
# 或一次执行类型检查、构建与测试：
npm run check
```

若需要真实消息代理集成测试，先将 `NATS_SERVER_BIN`（消息服务器可执行文件路径）设置为本机已有二进制的绝对路径，再运行检查。不设置时对应测试会跳过。

程序入口不自动读取根目录 `.env`（环境配置文件）。每个进程只注入自身所需配置，不能把含所有服务密钥的文件整体传给执行器。特别是原生辅助文件的 `CHAT_DATABASE_URL` 等服务专属变量，仍须在启动对应服务时映射为该进程使用的 `DATABASE_URL`（数据库连接串）。

### 11.2 配置文件与密钥归属

| 位置或配置 | 用途和注意事项 |
| --- | --- |
| 根目录 `.env` | 用户已有本地配置；不等于所有服务自动采用其中字段 |
| `dsh-agent-deploy/.env` | 容器组合部署配置，由 `init-dev.mjs` 补充随机密钥；不覆盖既有值 |
| `.local/native/.env` | 原生 PostgreSQL 与 S3 独立凭据，不自动与容器配置同步 |
| `.local/native/settings.json` | 本机 PostgreSQL 二进制位置，不是通用部署配置 |
| `.local/native/platform.json` | 原生各服务密钥、身份用户与管理员凭据、Java 路径；仅本机私密保存 |
| `.local/native/knowledge-sources.json` | 原生知识检索模式和实际用户访问名单 |
| `.local/native/seaweedfs.json` | 本机对象存储身份配置，包含访问密钥，不提交版本控制 |
| `DEEPSEEK_API_KEY`（模型密钥） | 执行器启用时必填；不要放定义文件、浏览器或命令参数 |
| `DEEPSEEK_BASE_URL`（模型源站） | 执行入口要求 HTTPS（加密超文本传输协议）；模型名来自授权定义 |
| `RUNTIME_ENABLED`（执行开关） | 默认关闭；启用前审查排队任务、模型、权限和预算 |
| `POINTS_BILLING_ENABLED`（计费开关） | 默认关闭；独立于执行器开关 |

`.env`、`.env.*`、`.local/`、`.tools/` 已被版本控制忽略；本地数据目录也已排除容器构建上下文。忽略规则不是加密或备份措施，不要把这些文件粘贴到日志、工单或公开文档。

### 11.3 Docker Compose（容器组合编排）路径

仓库包含 PostgreSQL、Keycloak、NATS、初始化/迁移任务和业务服务配置，执行器为可选且默认关闭。对象存储须单独准备；组合文件不会自动部署 SeaweedFS 或创建私有桶。

```powershell
node dsh-agent-deploy/init-dev.mjs
# 先按部署说明填写私有 S3 端点、桶和凭据；确保 Docker 引擎可用。
docker compose --env-file dsh-agent-deploy/.env -f dsh-agent-deploy/compose.yaml config --quiet
docker compose --env-file dsh-agent-deploy/.env -f dsh-agent-deploy/compose.yaml up --build -d
```

组合配置中的本机入口为聚合服务 `http://localhost:8080`、身份服务 `http://localhost:8081`、事件服务 `http://localhost:8082`；这些是配置地址，不表示当前已经在线。数据库和内部业务服务不映射宿主端口。

对象桶必须私有，并支持 `If-None-Match: *`（对象不存在才允许写入）。对象访问账号应限定到专用桶。生产对象存储要求加密连接，不能通过伪装开发环境绕过检查。完整首次部署及旧卷升级说明见 [部署工程](../dsh-agent-deploy/README.md)。

### 12.2 监控范围

会话、工作区、运行控制提供独立凭据保护的指标，覆盖发件箱、投影、支撑投递、过期租约、对象回收，以及部分数据库容量。已有 Prometheus（指标采集系统）配置与告警模板，但未交付已经运行的监控服务器和通知接收器。

数据库全局积压不能把多个副本的相同读数相加；数据库操作数等进程级指标可以按相应语义聚合。指标抓取失败不能显示成“积压为零”。健康端点只证明各自实现检查的条件，不证明完整链路、模型或全部权限可用。

### 12.3 常见问题

| 现象 | 优先检查 | 不应采取的做法 |
| --- | --- | --- |
| 消息已 202，但一直无回答 | 执行开关、NATS 投递、运行状态、配额、定义、前一回答投影 | 重复更换幂等键发送；将排队称为模型已开始 |
| 返回 429（请求过多）或 503（服务不可用） | 建议重试时间、入口容量、新消息计数、数据库等待与依赖健康 | 无退避并发重试；把拒绝吞吐算成功容量 |
| 文件写入返回 409（冲突） | 重新读取版本，核对上一请求是否已经成功 | 自动取最新版本并盲目覆盖 |
| 事件约一分钟断开 | 短期凭证到期，刷新凭证并带游标重连 | 延长所有令牌或把令牌放地址栏 |
| 实时正文重复 | 是否同时拼接预览和旧最终分块，是否按事件去重 | 将最终快照追加到草稿 |
| 运行结束但积分仍冻结 | 调用报告是否齐全、未知用量、余额不足、支撑发件箱 | 把未知记零、直接删账本或冻结记录 |
| 取消后仍发现文件修改 | 是否存在已获最终授权的在途提交窗口 | 宣称取消可以回滚既有副作用 |
| 原生库报 3D000 | 库初始化是否完成；只生成密码文件不等于创建业务库 | 删除现有数据库目录 |
| 本机 8333 无法连接 | SeaweedFS 进程状态、启动日志、端口和初始化卡点 | 将下载成功当作存储已部署成功 |

备份必须协调 PostgreSQL 元数据和 S3 正文，并考虑对象回收窗口；仅复制一个数据库备份不保证所有文件可恢复。恢复、密钥轮换、扩缩容和故障切换仍需单独演练。

## 13. 后续工作与扩展约定

建议按以下顺序推进，避免新增功能建立在未验证依赖上：

1. **完善本机运维与恢复验证。** 原生完整部署和真实模型全链路已通过；后续补齐数据备份／恢复、日志轮转、进程监督、长期稳定性和故障演练。
2. **完成生产安全与容量验证。** 公司成员管理、全接口分布式限流、全链路队列容量、供应商请求/词元速率控制、原生数据库竞争、长连接和完整链路压测。
3. **消除已知扩展瓶颈。** 任务消费分片、全局调度热点治理、完整配额感知排队；不能仅扩大执行槽。
4. **完善运营功能。** 供应商对账、缺失计量处理、积分退款/回收、管理员授权接口、审计检索导出、监控通知和恢复演练。
5. **扩展业务能力。** 会话跨服务删除、大文件和历史恢复、强撤销、审批与工作流补偿。任意用户代码或第三方插件必须先补强安全沙箱。

开发约定：协议变更同步校验、生成文档和消费者；表结构变更新增迁移，不覆盖历史迁移；新工具默认拒绝、显式授权；网络结果不确定时采用既有幂等/版本协议；所有容量和状态承诺必须附实测范围。前端开发是独立工作，不能因为前端未完成而忽略后端验收缺口。
