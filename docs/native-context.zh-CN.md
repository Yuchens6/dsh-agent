# DSH 原生上下文管理

更新日期：2026-09-30。

## 职责划分

Chat（会话服务）保存和提供用户聊天记录，不决定模型记住哪几轮，不按总字符数截取历史，也不生成摘要。
Runtime（执行服务）将截至本次提问的完整记录按原始角色导入 DSH Session（原生会话），由官方上下文插件管理模型请求。
平台仍负责身份隔离、消息归属、未来消息排除、传输安全、计量、执行额度和取消；这些不是上下文裁剪策略。

本次删除了 Chat 最近 20 条用户消息的限制、Run Control（运行控制服务）的 64,000 字符检查，以及工作流中 40 条消息／64,000 字符的二次裁剪。
用户单条输入和最终输出的 32,000 字符业务限制仍保留；它们不是会话总上下文窗口。

## 原生能力

- `dsh-session`（原生会话）：保存模型可见消息及消息替换关系，生成请求消息序列。
- `dsh-token-meter`（词元估算器）：依据原生事件与供应商用量估算上下文压力；缺少可信用量时采用官方启发式估算，不是精确分词器。
- `dsh-compaction-basic`（基础上下文压缩插件）：决定何时压缩、保留哪些近期消息、如何生成并替换摘要，以及如何恢复供应商确认的上下文溢出。

新增依赖与现有 DSH 版本一致，固定为 `0.1.1-rc.2`，没有修改上游源码，也没有实现平台自己的摘要算法。
普通智能体与原生工作流中的每个子智能体均使用该装配。

原生默认策略是达到路由模型窗口的 80% 时考虑压缩，近期保留预算为窗口的 16%，额外压缩尝试默认 1 次，确认溢出后的恢复默认最多 1 次。
这些是当前固定版本 DSH 的策略，不是 Chat 的消息筛选规则。
容量从模型适配器取得；当前平台 DeepSeek 适配器的回退配置仍为 128,000 词元，不能当作所选真实模型容量的自动发现结果。
实际部署应核对模型容量与适配器配置，不能将 128,000 词元、128,000 字符或 20 轮对话混为一谈。

## 历史导入与执行

1. Chat 锁定并检查本人会话和目标用户消息，按数据库顺序分页读取截至目标提问的用户消息及对应回复。
2. 每批 100 条用户记录只是读取批量；所有批次均被导出，不是保留最近 100 条。
3. Run Control 冻结授权输入，不重新选择历史。
4. Runtime 将历史按原始用户／助手角色导入原生会话种子；当前提问单独提交，不再把全部历史包成一条用户文本。
5. DSH 自行构建请求并执行压缩。工作流只附加上一成功步骤输出，不丢弃旧聊天历史。
6. 最终答案仍经原有结果投影写回 Chat；压缩摘要不改写或删除用户聊天记录。

重要边界：导入的是文本聊天记录，不是完整的历史 DSH 执行日志。原来的工具调用、推理、请求头和压缩检查点没有跨轮保存。
当前每个运行／工作流步骤重建原生会话，因此摘要可能在后续运行重新生成并再次计费；尚未实现原生会话的持久化恢复。
完整恢复应由 Runtime 保存／加载 DSH 原生日志，平台存储层只保管与授权，不分析摘要或挑选消息。此项没有在本次实现中冒充完成。

固定版本的自动压缩在步骤边界读取最近已记录的模型请求头。刚导入历史、尚无请求头时，首个请求可能先遇到供应商上下文溢出，再由原生插件恢复。
没有可压缩历史、单条不可分割内容过大、系统提示或工具定义本身过大时，不保证能恢复；失败不会偷偷丢弃消息。

## 计量、重试与失败

摘要是额外模型调用，同样先确认开始计量、结束后报告用量，使用同一模型、原总时限、步骤及运行的 `maxTurns`（最大模型调用次数）预算。
摘要输出上限取原生默认 8192 与当前单次输出上限的较小值，避免绕过已预留的输出预算。
例如：首次请求溢出、摘要、恢复后回答，共需 3 次调用额度；不足则失败，不提高预算或重新预留。

摘要正文不会进入用户回答预览；其计量仍会产生既有模型等待状态。压缩失败调用的用量未知仍然是未知，不能当作零费用。
原生摘要调用不是普通智能体循环请求，不能假定会享受同样的瞬时错误重试；保留原生插件自己的失败与收敛语义。
计量确认失败、取消、租约失效或预算耗尽仍失败关闭。已发生的工具副作用不会因压缩、失败或取消自动回滚。

## 传输与兼容边界

为防止无界读取占满数据库、服务进程和子进程，完整历史的序列化 UTF-8（八位统一字符编码）数据上限为 8 MiB（兆二进制字节），执行输入读取通道上限为 16 MiB。
这些是传输和内存保护：超限整体拒绝，Chat 返回 HTTP 413（请求数据过大），下游运行失败；不会返回删减历史，不把它当成模型窗口。
下一阶段若要支持超过该传输规模的长会话，应增加原生日志持久化和增量载入，不能重新引入“只取最近若干轮”的静默裁剪。
其他接口仍保持原有更小的请求／响应限制，不因为长历史放宽工具或公开接口。

`truncated`（已截断）字段暂时保留用于读取旧快照，新 Chat 始终返回 `false`（否）。
旧的已裁剪快照不能恢复已遗漏记录，执行器明确拒绝执行；已有历史查询不受影响。
升级需排空旧在途运行，统一更新协议、Chat、Run Control 与 Runtime；不应混用旧裁剪执行器。
本次没有数据库迁移、真实模型调用、密钥变更或实际服务重启。

## 验证

本机协议夹具覆盖超过 20 次提问、跨 100 条读取批次、超过 64,000 字符、原始角色保留、原生词元压力压缩、
确认溢出后恢复、摘要不作为回答预览、逐调用计量、调用预算、计量故障、旧裁剪快照拒绝和传输超限不删记录。
模型响应由本机模拟服务提供；不能代替真实模型窗口、摘要质量、费用及生产容量验收。
