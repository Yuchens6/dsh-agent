# 模型用量采集与统计

本阶段记录供应商返回的真实计量字段，不使用字符数或回答长度估算词元。
实现使用已安装的 DSH（DeepSeek 智能体执行框架）`0.1.1-rc.2` 适配器；测试调用本机模拟模型，尚未用真实供应商响应完成线上验收。
本功能不接支付，不计算货币价格，也不改变已有保守输出预算。

## 服务分工

| 项目 | 职责 |
| --- | --- |
| `dsh-agent-runtime-dsh`（执行服务） | 在每次模型流开始前上报调用开始；结束时读取适配器用量，等待确认；父进程转发，子进程无服务密钥 |
| `dsh-agent-run-control`（运行控制服务） | 校验执行身份、租约、输入快照及调用序号；从自身快照取得用户、租户和模型；本地事务保存调用记录与 Outbox（事务发件箱） |
| `dsh-agent-quota`（配额服务） | 接收运行控制的可信计量事件，核对预留所有者；按调用去重，保存用量，提供本人每日统计 |
| `dsh-agent-api`（前端聚合服务） | 验证用户身份和查询参数，把本人查询交给配额服务；不存用量，不计算费用 |

服务只通过协议调用，不读取其他服务的数据库。没有新增服务、长期凭据或公网内部接口。
用量转发沿用运行控制到配额的独立密钥，不能使用用户或执行器令牌直接写入配额服务。

## 调用与可靠性

每次模型调用使用“运行标识、尝试编号、调用序号”作为幂等身份。
调用开始必须有有效租约和冻结输入，序号从 1 连续递增，上一调用已完成计量才能开始下一次，且不超过定义的模型步骤上限。
开始记录和投递票据在同一事务提交；未收到开始确认不发起模型请求。
这条记录表示调用意图获准，不保证请求已经抵达供应商，因此不能把调用次数直接当成计费次数。

最终用量经子进程通信交给父进程，上报运行控制并等待确认后，才放行模型流结束。
传输失败最多重传同一报告三次，不重跑模型；仍失败则停止该运行。
运行控制到配额采用持久发件箱及退避重试，复用现有支撑票据积压指标和告警。
配额服务故障时可继续保存本地计量，但新运行仍受原有预算预留门禁约束。

取消、超时及失败不代表没有模型消耗。同一执行身份可在租约失效后补记已经开始调用的最终用量，
但不能新增调用、恢复租约或使用工作区工具。已保存的最终报告不可更改，冲突返回 409。
消费端支持最终事件先于开始事件抵达，后到的开始事件不会覆盖最终结果；重复投递不重复累计。

进程强杀、网络断开或供应商未提供用量时，无法保证获得完整计量：

- `reportedCalls`（已有用量调用数）：收到且通过校验的供应商用量。
- `unknownCalls`（用量未知调用数）：收到最终报告，但计量缺失或无效。
- `pendingCalls`（待报调用数）：已保存开始记录，尚无最终报告，可能执行中，也可能已崩溃。
- `startedCalls`（已记录调用意图数）：以上三项之和。

待报记录不会凭超时自动变成零；未知报告不伪造退款。平台不存模型原始响应或敏感正文到计量表。
发布前旧运行不回填用量；没有记录不能证明历史上没有消耗。

## 统计接口

`GET /api/v1/usage?day=2026-09-21`（查询本人指定日期模型用量）。
`day`（日期）可省略，默认 UTC（协调世界时）当天；只接受真实日历日期，拒绝用户或租户覆盖参数。
统计按运行控制记录的调用开始日期归属；跨午夜结束的调用仍属于开始那天。
结果异步更新，不保证模型刚结束时配额侧已经收到事件。

| 字段 | 中文含义与边界 |
| --- | --- |
| `accounting=provider-reported` | 供应商上报计量，非支付账本 |
| `inputTokens` | 不含已报告缓存命中的普通输入词元 |
| `cacheReadTokens` | 已报告的缓存命中输入词元，与普通输入互斥 |
| `outputTokens` | 输出词元，包含其中的推理词元 |
| `reasoningTokens` | 已报告的推理词元，是输出的子集，不能再次加到总量 |
| `cacheReadReportedCalls` | 提供了缓存命中字段的调用数；未提供不等于零命中 |
| `reasoningReportedCalls` | 提供了推理字段的调用数；未提供不等于零推理 |

四个词元累计字段使用十进制字符串，避免大累计值被 JavaScript（脚本语言）数字精度截断。
数值只汇总已知字段，必须结合覆盖计数解读；即使总数为 `"0"`，也不能忽略未知或待报调用。
缓存细分字段缺失时，适配器的输入计数无法再按缓存命中拆分；不基于缺失信息计算价格。

`GET /api/v1/quota`（查询本人配额）保留原有语义：每日输出上限预留和并发控制。
真实用量与保守预留并列保存，原保守预算不回退。第十一阶段可独立启用积分计价，见 [积分计费说明](points-billing.zh-CN.md)。

## 升级与未完成项

运行控制执行第四版迁移，配额执行第二版迁移。停入口写入与执行器后，先迁移并升级配额，
再升级运行控制和聚合服务，最后升级执行器；不得混用旧运行控制消费者处理新增计量票据。
启用模型仍需要单独配置和待运行任务确认，不因本次升级自动开启。

本节升级版本记录第九阶段历史；当前版本以部署说明为准。第十一阶段新增可配置人民币单价与积分结算；
仍未提供供应商账单对账、历史缺失计量补偿、支付充值、套餐、月度汇总、管理员查询和数据归档。
原生 PostgreSQL（关系型数据库）多连接竞争、真实模型计量和生产负载验收仍待环境就绪。
