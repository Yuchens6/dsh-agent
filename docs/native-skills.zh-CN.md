# DSH 原生技能与能力复用边界

更新日期：2026-10-07。DSH（DeepSeek 智能体执行框架）插件固定为 `0.1.1-rc.2`。本次只改平台适配层，不修改上游源码、不启用默认全功能程序。

## 1. 实现职责

移除执行器把全部 Skill（技能）正文拼入 System Prompt（系统提示词）的逻辑，改为安装官方 `dsh-skill`（技能注册表）和 `dsh-tool-skill`（技能工具插件）。平台通过原生 `ctx.skills.register()` 注册授权定义中的内存技能，不复制目录渲染、名字匹配、调用策略、正文包装或加载算法。

| 职责 | 实现方 |
| --- | --- |
| 审核、不可变版本、租户授权、冻结输入 | Catalog（定义中心）与 Run Control（运行控制服务） |
| 将冻结技能映射为原生注册项 | Runtime（执行服务）的 `skills.ts` 适配器 |
| 技能目录、模型加载工具、用户显式调用、会话记录 | DSH 官方技能插件 |
| 权限、共享预算、计量、取消和公开进度 | 平台服务与 DSH 原生工具 Guard（拒绝型守卫）适配 |

技能正文不能增加工具、工作区、网络或凭据权限；使用原生能力不等于取消平台授权。

## 2. 用户如何使用

模型按需调用：模型先收到名称和描述组成的原生目录，匹配任务后调用 `skill({name: "document-review"})`。正文只出现在加载后的 Tool Result（工具结果）中，不预先常驻系统提示词。目录和结果写入本次 DSH Session（原生会话）。

用户显式调用：普通聊天消息写入 `请 /brief-answer 总结这段内容`。DSH 识别空白边界上的 `/技能名` 并注入完整正文。同一步重复名称只注入一次；路径 `/usr/bin`、分数 `5/8` 不当作调用。未知或禁止用户调用的名称保持普通文本。平台没有新增命令解析器或前端专用接口。

| `invocation`（调用策略） | 模型目录及工具 | 用户显式调用 |
| --- | --- | --- |
| `modelInvocable: true, userInvocable: true` | 允许 | 允许 |
| `modelInvocable: true, userInvocable: false` | 允许 | 不注入 |
| `modelInvocable: false, userInvocable: true` | 不列出；工具拒绝 | 允许 |
| 两者均为 `false`（否） | 不列出；工具拒绝 | 不注入 |

策略控制加载途径，不是秘密保护：不要把密钥或机密放在技能中。模型自动选择不保证每个自然语言请求都会触发加载；必须每次生效的规则应放在系统提示词，安全约束必须由服务端落实。

## 3. 定义与兼容性

保留 `skills`（技能数组）的 `id`（标识）、`version`（版本）、`instructions`（指令）字段，增加三个可选字段：

- `name`（原生名称）：小写字母、数字和单个连字符组成，省略时使用 `id`。旧标识 `Review_Internal` 必须另配 `name: "document-review"`，不静默改名。名称和标识分别不能重复。
- `description`（路由描述）：建议写清任务触发条件。旧定义省略时使用名称与版本生成通用描述，不从正文抽取摘要。
- `invocation`（调用策略）：省略时两种途径均允许；显式设置时须提供两个布尔字段。

符合原生命名规则的旧定义仍可解析，但行为从“所有正文始终加载”变为“按需或显式加载”。部署前应审查既有技能：必要常驻规则移至系统提示词，补充技能描述并发布新定义版本。已发布版本不能原地改写，冻结输入不会被追溯更新。现有三个默认示例的技能数组为空，不受该行为差异影响。

沿用最多 10 个技能、每个正文 8,000 字符；原生目录描述默认规范化并限制到 500 字符。这是定义与资源保护，不是平台模型上下文裁剪。

示例见 [原生技能助手定义](../dsh-agent-catalog/definitions/native-skills-agent.v1.json)。未自动发布或设为默认，模型名称也没有真实账号验收。构建后，由管理员配置定义中心管理数据库连接，再执行：

```powershell
npm run publish -w @dsh-agent/catalog -- --file definitions/native-skills-agent.v1.json --tenant local-dev
```

`local-dev`（本地开发租户）须替换为实际授权租户。省略 `--default`（设为默认）不会切换默认定义；新会话应绑定对应定义。无需数据库迁移或新密钥。部署时先更新公开事件消费者及运行控制，再更新运行器，避免旧校验器拒绝新的 `skill` 进度。

## 4. 预算、工作流与反馈

`skill` 是子进程内的只读内存工具，不调用工作区或知识服务。通过 DSH 原生工具守卫，与远程工具共同计入 `RUNTIME_MAX_TOOL_CALLS`（单次运行工具次数上限），所有工作流步骤共享计数。未知、禁用或无效技能调用经过守卫也消耗次数；超限中止，不启动下一次模型请求。

显式调用是原生上下文注入，不伪造工具调用或消耗工具次数；仍受技能数量／正文大小、输入大小、模型调用、计量、超时和事件容量保护。技能加载本身无模型费用，随后携带的正文按实际供应商用量计费。

工具进度为 `{kind: "tool", tool: "skill"}`。运行控制检查有效租约、冻结定义是否有技能、序号与容量；公开事件仅含工具名称及既有运行／步骤标识，不含正文、参数或资源提示。确认失败中止。`RuntimeTool`（进度工具类型）的扩展不扩大 `AgentToolCall`（远程工具请求）的权限。

工作流每步使用同一批准技能集和该步远程工具子集。技能不能给步骤新增写工具。正文不自动从上一步插件上下文带入下一步，由 DSH 按需加载；本次用户提问含显式调用时，各步原生插件都会处理。已有步骤输出传递规则不变。

## 5. 未开放能力与后续复用

没有挂载 `dsh-skill-filesystem`（文件系统技能提供器），不扫描宿主机 `.dsh`、`.agents` 或用户工作区，不接收技能目录、远程地址、脚本或可执行插件。原生资源提示明确无附带技能文件；技能工具不会运行脚本或下载引用文件。用户文件仍只能经授权工作区工具读取。

| 能力 | 当前状态及后续做法 |
| --- | --- |
| 模型循环、工具派发、模型重试 | 已复用原生实现；平台只加权限／预算／计量边界 |
| Workflow（工作流）与子智能体 | 已接入受审核原生模板；复杂流程继续扩展原生引擎，不在运行控制重建编排 |
| 技能 | 本轮完成原生注册表与加载器；未来资源提供器只接批准内容，不重写目录与加载算法 |
| Compaction（上下文压缩） | 已接入原生词元估算与压缩，不回退至平台固定轮数／字符裁剪 |
| 原生会话持久化与恢复 | 尚未接入；复用 `dsh-session-persistence`（会话持久化接口）的协调器及 `agents.resume()`（智能体恢复） |
| MCP（模型上下文协议） | 尚未开放；未来复用 DSH 客户端，仅允许批准端点，先补网络、凭据、工具授权，不自研协议客户端 |
| 任意命令／用户代码 | 不开放；需要独立安全沙箱，原生插件本身不是多租户安全边界 |

每次运行仍从 Chat（会话服务）的文本记录重建原生会话。原生技能目录、工具结果与压缩检查点没有跨运行保存。本轮没有实现原生会话恢复，也没有重启服务或调用真实模型。

持久化实施前须解决：租户／用户／会话绑定、失效租约写入拒绝、成功状态与回答投影一致性、消息游标去重、工作流子会话独立状态、旧格式拒绝、容量与保留策略。平台仅实现存储授权和提交适配，不复制原生日志修复算法。原生“修复中断日志”不等于可以安全重跑有副作用的任务，不能简单共享本地目录就宣称完成恢复。

新增功能前核对实际安装版本的接口与行为，本地上游检出不保证与发布包一致。本轮测试使用真实已发布 DSH 插件与本机模拟模型，不以自制同名工具代替原生接入。

## 6. 验证结果

2026-10-07 全量 `npm run check`（类型检查、十一包构建及回归测试）通过：123 项全部通过、0 跳过，包含本机 NATS（消息系统）。原生插件实际运行于进程内与子进程测试，模型端是本机协议夹具，数据库采用 PGlite（轻量 PostgreSQL 引擎），不代表真实模型或生产部署验收。
