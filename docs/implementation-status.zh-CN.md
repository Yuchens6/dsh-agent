# 实现状态与下一阶段边界

本记录对应会话、事件、工作区、定义中心和运行控制链路，作为总架构设计的实施补充。
当前已推进到第十二阶段：入口并发保护、跨副本新消息限流、数据库等待上限、并行投递、主体调度并发与多执行槽；积分计费和 DSH 执行器仍默认关闭。后文历史验收按当时状态保留。

## 已落地

- 十个 TypeScript（带类型的 JavaScript）包独立编译，共用纯协议包；不跨服务导入业务实现。
- API 与 Stream 验证 RS256（RSA-SHA256 签名算法）身份令牌的签名、签发者、受众和有效期。
- Chat 对每个资源校验租户及所有者；客户端身份请求头不参与授权。
- 会话和消息使用 UUIDv7（第七版通用唯一标识符）、游标分页和幂等键。
- 消息与 Outbox（事务发件箱）同事务保存；代理故障后重发。
- 订阅能力令牌绑定主体和会话；SSE（服务器发送事件）具备重放、心跳、到期关闭与背压。
- Keycloak（身份管理平台）本地配置、数据库角色、容器编排及集群工作负载模板。
- OpenAPI 3.1（开放接口描述规范）由协议自动生成。
- Workspace（工作区服务）按租户/用户分配逻辑目录，提供虚拟路径文本文件读写、分页、版本检查和基础额度。
- PostgreSQL（关系型数据库）保存文件元数据，S3（简单存储服务）兼容存储保存不可变正文对象。
- 上传票据、预留容量和对象回收支持进程失败后重试；共享工作区行锁保证并发更新与回收一致性。
- Catalog（定义中心）通过受控命令发布不可变定义，按租户授权，在线进程采用独立只读数据库账号。
- 新会话绑定授权工作区和默认定义的精确版本；幂等重放不重新调用依赖，不改变已有绑定。
- 两个新服务的容器构建、集群部署、迁移、网络策略与工作区回收定时任务。
- Run Control（运行控制服务）独立消费持久任务请求，事务收件箱去重，同会话串行、全局并发限制。
- 运行租约、续期、取消、执行停止确认、超时失败和终态幂等回传；租约失效不自动重跑。
- 运行状态、输出和公开终态事件同事务保存；前端可以查询自己的运行结果或取消任务。
- 用户消息、公开接受事件与独立运行请求同事务保存；任务流没有时间淘汰，队列满时保留 Chat 发件箱。
- 按执行节点与有效租约获取持久输入快照；读取授权会话历史及精确版本定义，外部调用后重新检查取消与过期。
- 会话提供有界历史、问答关联与幂等助手消息写入；成功投影前阻止同会话下一轮和完成事件发布。
- 回答投影持久重试、指数退避；跨服务提交后确认丢失不会制造重复助手消息。
- 第二版数据库迁移、独立内部执行接口文档和专用服务凭据；没有跨服务数据库访问。
- 工作区运行能力令牌最长 30 秒且不超过租约与截止时间；每次操作在线核对执行节点、尝试编号、状态和工具名单。
- 执行器仅有列目录、读文本和条件写入接口，不能提交用户/租户/工作区标识；写入上传前与可见版本提交前重复授权。

Runtime DSH（DSH 执行服务）已复用租约输入快照、助手回答投影和受限工作区能力驱动模型循环；
非前端尚余范围见 [后端后续清单](backend-remaining.zh-CN.md)；本轮未开发前端。
前端聚合服务使用工作区文件管理接口；运行器必须使用单独的执行工具接口。
不得把工作区能力与授权服务的长期签名密钥给运行器；运行器仅持有自身工作节点身份密钥，不挂载用户共享目录。
旧会话中的空工作区绑定未回填，后续运行入口必须拒绝执行空绑定。

自动测试覆盖 PostgreSQL 兼容引擎上的迁移和事务、跨用户/租户隔离、幂等冲突、
消息发布失败恢复、真实 HTTP（超文本传输协议）服务调用，以及 SSE 生命周期和背压。
真实 NATS 测试用官方本地二进制启动隔离实例，验证消息重放和消费者释放。
新增测试覆盖跨用户/租户文件隔离、路径绕过、条件写入、目录冲突、上传失败回收、定义不可变、
租户授权、在线只读账号及真实 HTTP 跨服务会话绑定。S3 客户端使用本地协议夹具验证真实网络请求，
并非真实供应商端到端验收；仍需针对选定对象存储服务联调。

PGlite 是 PostgreSQL 引擎的 WebAssembly（可移植二进制执行格式）版本，
不是生产数据库部署。它无法证明多副本原生 PostgreSQL 上的全部锁竞争行为。
Docker 引擎未运行、Kubernetes 未配置集群上下文，因此容器启动、Keycloak 导入、
网关控制器验收和集群网络隔离测试仍待环境就绪后执行。
