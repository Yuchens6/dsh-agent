# 本地原生部署测试用例

版本：1.1；日期：2026-10-14；适用工作区：`D:\code\dsh`。

结果文件：[首次本地测试报告](local-test-report-2026-10-11.zh-CN.md)、[提交后复测报告](local-test-report-2026-10-14.zh-CN.md)。本文定义可复现步骤和判定标准，不把预期结果当作实际执行结果。

## 1. 测试目标与前置条件

验证现有 Windows（视窗操作系统）原生 Agent（智能体）后端的功能、访问控制、数据持久化和小规模实时反馈，不使用 Docker（容器工具）或 Kubernetes（容器编排平台）。

运行前必须满足：

1. 按[原生部署手册](../native-deployment.zh-CN.md)完成初始化；10 个应用服务和 PostgreSQL（关系型数据库）、Keycloak（身份管理平台）、NATS JetStream（持久化消息流）、SeaweedFS（对象存储）均已启动。
2. `.local/native/platform.json` 中两个测试用户能够登录；普通用户称为 A，隔离验证用户称为 B；两者属于同一测试租户、用户标识不同。脚本内部读取凭据，不把密码写入输出。
3. 默认定义为 `local-agent` 第 1 版，`local-workflow` 第 1 版已发布；知识源 `local-handbook` 使用 PostgreSQL 后端，包含合成公司手册，仅授权 A。
4. 根环境文件中的模型配置可用；只有明确传入 `-LiveModel`（真实模型开关）才执行新的外部模型调用。积分计费保持关闭。
5. 当前环境保留此前的 `verification.json`（对话验收记录）和 `workflow-verification.json`（工作流验收记录），供历史证据复核；全新环境缺少历史记录时不能将对应检查记为通过。
6. 运行期间不要修改业务代码、默认定义或知识源，不要同时重启服务。测试不是生产迁移脚本，也不是故障注入或压测工具。

## 2. 执行入口与证据

在工作区根目录运行：

```powershell
cd D:\code\dsh

# 状态检查；如果尚未启动，先执行 -Action Start
.\dsh-agent-deploy\native\platform.ps1 -Action Status

# 完整回归、基础设施和本地接口验收；不产生新的外部模型调用
.\dsh-agent-deploy\native\test-suite.ps1

# 增加两轮合成内容的真实模型测试，会产生供应商费用
.\dsh-agent-deploy\native\test-suite.ps1 -LiveModel
```

套件按顺序执行：环境与代码快照 → 启动前状态 → 类型检查 → 12 包构建 → 137 项代码回归 → 基础设施检查 → 38 项本地验收 → 可选真实模型测试 → 结束状态。状态命令仅展示进程状态，返回成功不意味着所有服务已经启动；真实依赖由后续检查验证。

每次执行创建独立 `.local/native/test-reports/<运行编号>/`，包含环境、代码散列、阶段退出码、逐用例 JSON（结构化文本数据）、回归 TAP（测试结果文本协议）日志及真实模型证据。第一次失败即停止后续阶段，失败阶段后的用例是**未执行**，不是通过。测试后保留服务运行。

也可单独运行 38 项本地检查：

```powershell
node dsh-agent-deploy/native/acceptance.mjs ".local/native/test-reports/manual-20261011-01"
```

单独运行时必须给出新的子目录名称，避免覆盖上一份证据。本地检查本身不执行模型、不切换默认定义、不重新导入知识数据。

## 3. 38 项本地验收用例

以下 HTTP（超文本传输协议）业务路径默认在 `http://127.0.0.1:8080/api/v1` 下。正向接口采用用户 A 的真实访问令牌；跨用户检查使用 B。`workspaceId`（工作区标识）与 `sessionId`（会话标识）来自本次请求，不写死已有用户资源。

## 4. 基础设施专项用例

入口为 `infra.mjs verify`（基础设施验证程序），套件自动调用，所有目标均来自原生部署配置。

| 分组 | 主要步骤 | 通过标准 |
| --- | --- | --- |
| INF-DB | 连接真实 PostgreSQL；11 个服务账号登录；检查跨模式拒绝；使用错误密码连接 | 正确账号可连接；未授权模式不可用；错误密码 SQLSTATE（数据库状态码）为 `28P01` |
| INF-S3-DATA | 私有桶中创建随机探测对象，读取中文正文，重复条件写入，删除后再读 | 正文一致；重复写返回 412 且原对象不变；删除后 404 |
| INF-S3-AUTH | 匿名访问桶／对象、错误签名访问、尝试创建权限范围外的随机桶 | 全部 403；不实际创建外部桶；探测对象清理 |

S3（简单存储服务）条件写入使用 `If-None-Match: *`（仅对象不存在时写入）。不执行删除现有桶、递归清空对象等破坏性操作。

## 5. 真实模型测试用例

入口为 `client.mjs test`（本地对话冒烟测试），仅在套件的 `-LiveModel` 开关启用时执行。沿用根环境文件的模型，用户内容为合成验证文本。

| 编号 | 步骤 | 通过标准／证据 |
| --- | --- | --- |
| LIVE-01 | A 实际登录并获取本人身份 | 用户标识与配置一致 |
| LIVE-02 | 无令牌访问会话 | 返回 401 |
| LIVE-03 | 查询默认智能体与已发布工作流 | 两个定义存在且默认值正确 |
| LIVE-04 | 建立临时文件，验证读取、冲突、越界与 B 的拒绝 | 文件正确、409／400／403或404等边界符合脚本断言 |
| LIVE-05 | 幂等创建会话、检查 B 不可访问 | 同键返回同一会话；跨用户拒绝 |
| LIVE-06 | 让模型读取随机验证标识，再检索授权手册；接收状态和正文；读取最终历史；重放提交 | 实际观察到 `workspace.read` 和 `knowledge.search`；答案含正确标识与 PostgreSQL；有状态和正文预览；终态成功并落历史；重放返回同一消息 |
| LIVE-07 | 第二轮输入 `/brief-answer`，只问此前标识，不再允许读取文件或知识源 | 返回同一标识；公开工具事件为空；记录第二轮耗时 |
| LIVE-08 | 查询配额、用量与审计 | 三个接口成功；不将其等同于实际积分结算 |

**原生技能判定边界：** DSH（DeepSeek 智能体执行框架）显式 `/技能名` 由原生模块注入上下文，不产生工具执行事件。代码回归通过模型请求夹具验证技能正文确实注入、调用策略及去重；真实测试只验证该输入流程成功、历史标识保留且没有额外工具读取。模型主动调用 `skill`（技能工具）则是另一条路径，不能混为同一事件。

## 6. 回归与未覆盖项

代码回归会运行 `tests/*.test.ts`，自动设置 `NATS_SERVER_BIN`（消息服务器程序路径），缺失该程序会失败，不默默跳过。真实 NATS 用随机本机端口与临时目录；多数数据库测试采用 PGlite（轻量 PostgreSQL 引擎），模型采用合成响应；具体分层见测试报告。

本套件不覆盖：一万并发对话、持续负载与高分位延迟、恶意模型或宿主代码沙箱、真实公司组织管理全流程、生产加密入口、向量模型与外部 LightRAG（轻量知识图谱检索服务）部署、真实积分支付结算、长时间断电恢复、持续运行稳定性、浏览器前端交互。

## 7. 清理与安全

仅测试文件、S3 探测对象和回归临时数据库／消息目录会被清理；测试会话、审计、模型用量和报告保留。已存在的业务文件、账号、默认定义和数据库结构不被用例重置。测试报告不得包含模型密钥、访问令牌、数据库连接串或用户密码；`.local/native` 保持原有私有目录权限。
