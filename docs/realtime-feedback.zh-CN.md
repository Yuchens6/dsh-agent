# 实时反馈与流式正文：第十三阶段

本阶段实现后端协议和执行链路，不包含前端页面，不代表完成真实模型或一万长连接的部署验收。

## 用户反馈约定

| 时间点 | 信号 | 建议显示 |
| --- | --- | --- |
| 点击发送，尚无服务器确认 | 前端本地状态 | 正在发送 |
| 消息与待投递任务在数据库提交成功 | HTTP 202（超文本传输协议：已接受） | 已接收，等待处理 |
| 运行控制接纳任务 | `run.status.v1`，`phase=queued`（排队） | 正在排队 |
| 执行器领取任务 | `phase=preparing`（准备） | 正在准备上下文 |
| 调用开始计量已入库、准备发出模型请求 | `phase=waiting_model`（等待模型） | 正在请求模型，等待响应 |
| 暂时性模型错误，原生插件安排重试 | `phase=retrying_model`（模型重试等待），附失败调用编号、重试次数和等待毫秒 | 连接异常，正在重试；将该调用预览标记为未完成 |
| 收到正文片段 | `run.output.preview.v1`（输出预览） | 显示实时正文 |
| 即将执行受限工具 | `phase=tool`（工具操作）及工具名 | 正在读取／写入／列出文件 |
| 最终回答已成功写回会话 | `run.output.snapshot.v1`（完整输出快照），随后完成事件 | 用最终答案替换预览，结束加载 |
| 失败或取消 | 既有失败／取消事件 | 停止加载，预览标记为未完成，不作为成功答案 |

“思考中”只是等待模型的界面提示，不公开模型推理。等待状态在实际网络请求前产生，
不能据此保证供应商已经接受请求。排队不得伪装成模型正在思考。
202 之后仍可能因权限、积分、预算或执行错误而失败；429/503（限流／服务不可用）不得显示为已接收。

## 服务分工与可靠性

- Chat（会话服务）：保持短请求、事务发件箱与幂等键。接收确认不等待模型、消息代理或长连接。
- Run Control（运行控制服务）：在接纳／领取／计量开始事务中产生状态；校验执行租约并持久化进度。
  公开事件沿用 NATS JetStream（持久消息流）与事务发件箱；最终快照仍受会话回答投影屏障保护。
- Runtime DSH（DSH 执行服务）：只读取已安装框架的正文增量；不修改上游框架。
  IPC（进程间通信）收到父进程确认才继续，父进程等待进度入库，不等待任何浏览器客户端。
- Stream（流式服务）：复用 SSE（服务器发送事件）鉴权、会话隔离、白名单、游标恢复与慢消费者断开。
  不读运行控制数据库，不推断模型状态，不持有模型密钥。

内部接口 `POST /worker/v1/runs/{runId}/progress` 不能经公网网关暴露。
正文包含执行租约、连续序号及正文／工具状态白名单。租约、节点、运行状态与截止时间在行锁后检查。
同序号同正文只确认一次；不同正文冲突，跳号拒绝；取消或租约失效后连重复进度也拒绝。
正文必须对应已开始且尚未提交最终计量的调用；工作流还需对应当前步骤。
工具进度只表示意图，不授予文件权限，实际工具操作仍需在线授权。

每运行最多 4096 条执行器进度、累计 1 MiB（1048576 字节）预览正文；超过即拒绝，运行器终止该运行。
确认丢失时同序号重试，最多三次；持续故障时失败关闭，不重跑模型。
白名单不含工具参数、路径、内部推理或供应商私有字段。模型正文仍是不可信用户数据，前端必须转义，
不能作为 HTML（超文本标记语言）直接执行。

## 低延迟与有界缓冲

每次模型调用首个完整正文片段立即发送，此后默认按 75 毫秒或 2048 个 UTF-16（16 位统一字符编码）代码单元合并。
供应商停顿时，已有文本仍定时刷新；跨片段代理对拼完整后发送。
只预取一个供应商片段，单条进度确认在途，不建立无限内存队列。数据库／网络过慢仍会对执行器施加背压，
合并窗口不是端到端延迟保证；浏览器慢消费者不会直接阻塞模型。

Chat 与 Run Control 公开事件发布的空闲扫描从 500–624 毫秒缩短为 100–124 毫秒；忙时继续立即处理。
运行事件按最近服务时间轮转，避免持续输出的旧任务一直优先于其他任务的排队提示；同一运行仍按事件顺序发布。
执行器空闲领取仍为 1–1.25 秒，未引入分布式唤醒；接收／排队反馈不等待领取。
实时事件会增加数据库和消息代理写入量，需压测并保留连接池、租约续期及全局队列容量预算。

## 前端接入与兼容

建议进入会话即申请订阅并建立连接，提交消息后根据 202 直接更新接收状态，不能等待事件发布才反馈。
新增事件包含 `messageId`（用户消息标识）、`runId`（运行标识）、`attempt`（执行轮次）。
预览按 `(runId, attempt, call)`（运行、轮次、模型调用）分组；工作流另有 `stepId`（步骤标识）。
不同调用／步骤是不同草稿，不能直接拼成同一答案；可切换当前预览或独立展示步骤。
第十五阶段原生重试也会分配新的模型调用编号。`retrying_model` 的 `call` 指失败调用，`retry`/`maxRetries` 为已安排的重试序号/最大额外次数，`delayMs` 为退避时间；它不保证后续请求一定发出，也不包含供应商私有错误。没有前端页面实现，客户端须自行完成该状态展示。见 [模型重试设计](model-retry.zh-CN.md)。
`sequence`（序号）用于同一执行轮次去重，工具状态也占序号，正文序号有空洞不代表丢包。
所有事件另按 `eventId`（事件标识）去重，防止消息代理确认丢失后的重复投递。

最终快照必须替换整个预览，不能追加。失败／取消后，不得把迟到或回放的旧预览恢复为运行中。
若最终文本经 JSON（数据交换格式）编码超过 100000 字节，快照中的 `text`（文本）为 `null`（空值）；
客户端需调用现有授权运行查询取得完整 `output`（输出）。空值不表示空答案，避免转义放大后超过代理 128 KiB（131072 字节）单事件上限。
旧 `run.output.delta.v1`（输出分块）保留，仅在最终完成后产生，兼容旧客户端。
新客户端使用“预览 + 最终快照”，必须忽略旧分块，不能把两种协议的正文相加。

断线保存 `Last-Event-ID`（最后事件游标），刷新订阅凭证后携带游标恢复。游标过期时，
通过现有运行查询、会话历史恢复最终状态／回答；不承诺事件保留期外恢复全部草稿。
连接凭证仍为短期，仍有约 60 秒重连及每实例默认 1000 连接限制；未扩大额度或改变凭证安全期限。
客户端重连需随机抖动；一万长连接、消费者规模与网关限流还需验收。

## 升级与验证

Run Control 新增第 7 版迁移 `007_progress.sql`（进度序号、大小计数、幂等凭据表）。
先暂停新写入与执行、等待或取消在途运行并备份数据库，迁移后更新相关服务。
新运行器不能向旧运行控制报告进度，只认识旧事件的 Stream 也不能承接新客户端。

```powershell
docker compose --env-file dsh-agent-deploy/.env -f dsh-agent-deploy/compose.yaml run --rm --build run-control-migrate
```

Kubernetes（容器编排平台）迁移任务为 `dsh-agent-run-control-migrate-v7`。等待迁移成功后更新运行控制、执行器、流式服务、
会话服务及使用协议包的其他服务。既有环境文件、模型开关未自动修改。

测试覆盖：模拟供应商暂停结束帧时，真实 DSH 子进程正文经认证 HTTP、持久发件箱和 SSE 提前到达客户端；
定时刷新、字符边界、序号去重、权限拒绝、取消、事务回滚、大小限制、工作流调用编号、最终快照及兼容分块。
本地模拟测试不能替代原生 PostgreSQL（关系型数据库）锁竞争、真实模型首字时间和全链路负载验收。

包含本地真实 NATS 消息代理、真实 DSH 子进程与模拟模型。没有调用外部模型、部署容器、迁移实际业务库或推送远程代码。
