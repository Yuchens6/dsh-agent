# 真实模型与 DSH 原生执行验收

验收日期：2026-10-08。使用根目录 `.env`（环境配置文件）的实际凭据，未修改该文件或输出密钥。

## 配置与执行范围

实际配置是 `LLM_API_KEY`（模型密钥）、`LLM_BASE_URL`（模型地址）、`LLM_MODEL`（模型名称）。测试入口同时支持 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`，两组同类字段同时存在且值不一致时拒绝启动。

本次地址为 `https://api.deepseek.com`，模型为 `deepseek-v4-flash`。诊断脚本只接受该官方源站的根路径，不向其他地址发送凭据，不将 `.env` 整体载入子进程环境。

通过平台现有 `processExecutor`（子进程执行器）启动真实 DSH（DeepSeek 智能体执行框架）子进程、官方模型适配器、原生技能插件与工作流引擎，不是以直接接口请求代替智能体验收。一次运行结束后子进程退出，不创建永久服务或网页地址。

只发送合成指令，不上传项目文件、工作区内容或私人对话。远程工具集合为空，任何远程调用都会失败；每次模型请求最大输出 256 个 Token（词元），每个场景最长 60 秒，模型重试关闭，完整一轮最多 7 次模型请求。工作流最多两步，技能工具次数上限为 2。

## 实测结果

| 场景 | 供应商请求次数 | 首段正文时间 | 完成时间 | 验证 |
| --- | --- | --- | --- | --- |
| 普通对话 | 1 | 910 毫秒 | 954 毫秒 | 返回 `OK` |
| `/smoke-check` 显式技能 | 1 | 606 毫秒 | 692 毫秒 | 原生注入指令，返回 `READY`；未伪造工具调用 |
| 模型主动加载技能 | 2 | 1299 毫秒 | 1378 毫秒 | 实际调用原生 `skill` 工具后返回 `READY` |
| 两步条件工作流 | 2 | 697 毫秒 | 1274 毫秒 | 原生步骤依次开始／完成，条件满足后第二步返回 `READY` |

时间从测试启动本次 DSH 子进程开始计算，包含启动与模型网络请求；工作流首段正文来自第一步，不是最终答案。只是一轮小样本，不构成首字延迟保证或并发容量结论。

成功轮次共 6 次模型调用，供应商报告累计非缓存输入 1,199 词元、缓存输入 512 词元、输出 47 词元。缓存输入与非缓存输入分开记录，不能重复相加计价；此处未计算金额、未写入平台积分账本。

### 观察到的失败

此前用复杂下划线标记 `DSH_MODEL_OK` 验收时，两次 DSH 请求返回的文本未精确匹配。随后一次独立官方流式接口诊断也返回了不同文本，因此不能把现象归因于平台流式拼接。以上三次诊断同样属于真实付费请求，不包含在成功轮次的用量统计中。

后续改用简短标记 `OK`、`READY`、`FIRST`，仍严格校验回答、原生工具进度和工作流步骤顺序，并通过全部四个场景。该结果验证接入与执行链路，不代表模型已解决复杂标记复制或业务指令遵循问题。平台应继续使用结构校验，不能依赖模型始终准确复制文本。

## 重复执行

在仓库根目录执行：

```powershell
npm run build
npm run test:live:model -- --live
```

`--live`（明确启用真实请求）是必需参数；缺少时立即退出，不读取凭据或发送请求。该命令会消耗实际模型额度，不能加入默认离线测试或无人值守重复重试。

脚本位于 `dsh-agent-runtime-dsh/scripts/model-smoke.mjs`。脱敏结果保存到 `.local/model-smoke/latest.json`（最近一次报告），并写入带时间戳的独立报告；目录已被 Git（版本控制系统）忽略。报告包含固定测试回答、供应商用量、首段正文与总耗时，不记录密钥、请求头或环境文件正文。

## 未验收边界

本次启动的是平台使用的 DSH 子进程，不是全部平台后端。没有启动 IAM（身份管理）、Chat（会话服务）、Run Control（运行控制）、Workspace（工作区服务）、SSE（服务器发送事件）等常驻服务，没有运行数据库迁移、发布定义或调用实际知识库。

测试中的进度和计量确认由本地诊断回调提供，不经过生产运行控制数据库或积分结算。完整微服务链路仍需独立部署与验收；跨轮原生会话恢复依然未实现。

测试入口兼容 `LLM_*` 字段不等于生产服务配置已改变：生产运行器仍读取 `DEEPSEEK_API_KEY` 与 `DEEPSEEK_BASE_URL`，模型名称来自批准的 Catalog（定义中心）版本，并需要运行控制地址、服务凭据等其他配置。不得把根目录 `.env` 中的所有变量无差别注入每个服务。
