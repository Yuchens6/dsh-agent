# 模型请求有限重试

日期：2026-09-28。复用官方 DSH（DeepSeek 智能体执行框架）`@deepseek-ai/dsh-llm-retry@0.1.1-rc.2`，没有修改上游源码或自研重试循环。接入针对有效运行内部的失败模型请求，不提供失败运行重新执行接口，不重跑成功工具，不恢复失效租约。

## 策略与配置

适配器提供 `retryPolicy`（重试策略），执行引擎挂载原生插件，在 `agent/request-error`（模型请求错误扩展点）执行恢复。仅启用 `normal`（有限重试）模式，允许 `EMPTY_RESPONSE`（空响应）、`RATE_LIMIT`（限流）、`SERVER`（服务端错误）、`TIMEOUT`（超时）、`TRANSPORT`（传输错误）。鉴权、无效参数、权限和工具错误不由该机制重试；分类以固定版适配器为准，不把所有 HTTP 429（请求过多）都假定为可恢复。

| 执行器环境配置 | 默认 | 范围与含义 |
| --- | --- | --- |
| `RUNTIME_MODEL_MAX_RETRIES` | 2 | 0–5，首次请求之外的最大重试次数，0 关闭 |
| `RUNTIME_MODEL_RETRY_INITIAL_MS` | 500 | 1–10000，初始退避毫秒 |
| `RUNTIME_MODEL_RETRY_MAX_MS` | 10000 | 1–10000，最大退避毫秒，不小于初始值 |

采用 Exponential Backoff（指数退避）和 10% Jitter（随机抖动）。合法 `Retry-After`（供应商建议等待时间）不超过最大值时优先遵守，超过时不提前重试。配置只由部署方设置，不接受用户提示词修改；没有无限重试模式。Compose（容器组合编排）已映射这些变量，原生 Node.js（脚本运行时）进程通过环境变量读取。未修改实际 `.env`（环境配置）、执行开关、计费开关或凭据；默认执行器仍关闭。

## 预算、期限与取消

- 每次真正进入模型流的尝试拥有新的 `call`（调用编号），包含重试；`maxTurns`（最大模型调用次数）包含首次请求、工具循环和重试。剩余调用预算不足时不安排重试，最大次数不是保证获得的次数。
- 工作流每一步仍有独立调用预算；父进程把步骤内编号映射为整运行连续编号。原生恢复不会重置全局调用预算、工具预算或步骤预算。
- 退避、重试请求共用原运行取消信号和截止时间，不延长租约或任务总时限。父进程续租失败、服务停机、用户取消均终止执行。
- 进度、计量确认失败属于平台故障，执行引擎失败关闭，不将它伪装为供应商错误重试。
- 完整回答仍只通过既有幂等终态提交和会话结果投影入库；即使模型恢复成功，也要通过有效租约验证才能提交。

## 用量与费用

每次尝试在网络请求前等待开始计量确认，结束时保存供应商实际用量。失败请求没有可信用量时记为未知，不能推断为零；恢复成功后，先前未知调用仍可能使积分保持 `pending_usage`（等待用量）与冻结状态。当前没有自动向供应商拉取账单补全该未知值，也没有人工强制置零接口，启用计费前必须确认这一运维边界。重复输入可能再次收费，框架重试不提供供应商费用的“恰好一次”保证。

## 实时状态与草稿

新增 `run.status.v1`（运行状态事件）的 `phase=retrying_model`（模型重试等待）：

```json
{"phase":"retrying_model","call":2,"retry":1,"maxRetries":2,"delayMs":500}
```

`call` 指失败调用，不是下一调用；`retry` 为当前失败链的额外尝试序号；工作流另附 `stepId`（步骤标识）。只发布白名单数值，不公开上游错误正文、请求头、路径或密钥。状态先通过既有进度协议持久确认，下一模型请求开始前等待确认。事件记录“安排重试”，不保证在取消或截止之前一定执行。

服务端要求有效运行/租约、当前步骤、失败调用已提交终态计量、该调用为最新且有剩余预算；仍使用进度序号和内容摘要去重。框架在失败后不会把该次未完成正文作为成功历史继续送给模型。客户端应将该调用草稿标为未完成，下一调用单独显示，最终快照替换预览，不能拼接重试前后的正文。前端页面本轮未实现。

## 升级与验证

没有新增数据库迁移，运行控制仍需第 7 版。先更新公共协议、运行控制与流式服务，再更新执行器；旧服务可能拒绝新重试状态，滚动升级期间可设置 `RUNTIME_MODEL_MAX_RETRIES=0`。运行 `npm ci`（按锁文件安装依赖）和 `npm run check`（类型检查、构建、回归测试）。上游会话事件仍仅保存在本次子进程；公开重试状态持久化到平台发件箱，不表示全部 DSH 事件已经实现持久恢复。

针对性测试使用真实固定版 DSH 和本机模拟模型：暂时性错误恢复、次数耗尽、关闭重试、总调用预算、永久错误、供应商等待上限、退避取消、断流预览、成功工具不重做、计量/进度失败关闭、真实子进程通信，以及工作流全局调用编号和持久投影。不调用外部模型，不以这些测试宣称供应商真实账单或生产网络已验收。
